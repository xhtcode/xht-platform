## 1. 项目概述

### 1.1 项目用途

基于 Spring Cloud Alibaba 的企业级微服务底座：**分布式认证中心 + 网关 + 分层后台管理 + 代码生成**。配套后台前端为独立仓库（Vue 3 + Element Plus，不在本仓库内）。

### 1.2 技术栈

| 分类 | 选型 |
| --- | --- |
| 运行环境 | Java 17、Maven 3.8+（多模块聚合，父 POM 为 `xht-framework-parent`） |
| 核心框架 | Spring Boot 3.5.15、Spring Cloud 2025.0.3、Spring Cloud Alibaba 2025.0.0.0 |
| 认证授权 | Spring Security + OAuth2 Authorization Server、OIDC、JWT / Opaque Token |
| 服务治理 | Nacos（注册 + 配置，参数经 Maven profile 注入）、OpenFeign、LoadBalancer |
| 网关 | Spring Cloud Gateway（WebFlux） |
| 数据访问 | MyBatis-Plus 3.5.16、MySQL 8+；逻辑删除 + 字段自动填充 |
| 缓存 / 会话 | Redis 7+（`RedisRepository` 封装）、Spring Session |
| 对象转换 | MapStruct 1.6.3、Lombok 1.18.36 |
| API 文档 | SpringDoc OpenAPI、Knife4j（启动类须标 `@EnableCustomSwagger`） |
| 工具库 | Hutool 5.8.42、Commons Lang3、Commons IO |

### 1.3 四个可独立部署的服务

| 服务 | 端口 | 启动类 | 职责 |
| --- | --- | --- | --- |
| xht-auth | 9000 | `com.xht.auth.AuthApplication` | OAuth2 授权服务器，**必须最先启动** |
| xht-admin | 8081 | `com.xht.platform.AdminApplication` | 后台管理（用户/角色/菜单/部门/字典/通知/文件等） |
| xht-generate | 9700 | `com.xht.platform.GenerateApplication` | 代码生成 |
| xht-gateway | 8080 | `com.xht.gateway.GatewayApplication` | 统一入口，路由 `/auth/**`、`/admin/**`、`/generate/**` |

### 1.4 术语表

| 术语 | 含义 | 所在层 |
| --- | --- | --- |
| `Form` | 新增/修改的提交对象，继承 `BasicForm` | domain |
| `Query` | 查询条件对象，继承 `PageBasicQuery` 或 `BasicQuery` | domain |
| `Response` | 对外返回的视图对象，通常是 Entity 的子集 | domain |
| `VO` | 聚合视图对象（跨表、跨服务拼装），继承 `BasicResponse` | domain |
| `BO` | 仅服务内部使用的业务对象，不外泄 | infrastructure |
| `Entity` | 与数据库表一一映射的持久化对象 | infrastructure |
| `Converter` | Entity 与 Form/Response/VO 之间的转换器（MapStruct） | infrastructure |
| `DAO` | 数据访问仓储接口，屏蔽 Mapper 细节 | infrastructure |
| `Common` | 模块级公共包（`xht-admin-common` / `xht-generate-common`），放跨层复用的契约、枚举、常量、工具 | common |
| `Api 契约` | 服务间调用接口签名（`IXxxClient`），放在 common 的 `{域}/api`，服务端与调用方共用同一份 | common |
| `Client` | 服务间调用装配模块（`xht-platform-client-*`），负责注册 Feign、注入降级、向外暴露门面 | client |
| `门面（Factory/Publisher）` | 业务真正注入的接口（`ISysDictFactory`、`IMessagePublisher`），隔离 Feign 与缓存细节 | common |

## 2. 目录结构与模块职责

### 2.1 模块全景

```
xht-platform
├── doc                               # 文档：sql 初始化脚本、安装部署、本规范
├── xht-framework-parent              # 框架父工程：core + dependencies(BOM) + 10 个 starter
│   ├── xht-framework-dependencies    #   依赖版本 BOM（无源码），三方版本只在这里定
│   ├── xht-framework-core            #   核心库：R、异常体系、BasicEntity、AssertUtils、工具类
│   └── xht-*-spring-boot-starter     #   cache / web / mybatis-plus / security / resource-server /
│                                     #   openfeign / log / sms / swagger / spring-cloud 共 10 个
├── xht-auth                          # 认证中心（单体服务，不分层，包按功能域：authentication/captcha/...）
├── xht-gateway                       # 网关（WebFlux，单体服务，不分层）
├── xht-admin                         # 后台管理服务 —— 四层结构
│   ├── xht-admin-adapter             #   Controller、内部 Feign 服务端 client/*
│   ├── xht-admin-domain              #   form/query/response/vo、enums、Service 接口
│   ├── xht-admin-infrastructure      #   Service 实现、dao/entity/converter、properties/manager、mapper xml
│   └── xht-admin-start               #   启动类、application.yml、logback-spring.xml
├── xht-generate                      # 代码生成服务 —— 同样四层（adapter/domain/infrastructure/start）
├── xht-platform-common               # 模块级公共包，一服务一包，无业务实现
│   ├── xht-admin-common              #   admin 的公共包：Feign 契约、契约 VO、门面、文件工具、站内信模型
│   └── xht-generate-common           #   generate 的公共包：生成器常量、生成器枚举
└── xht-platform-client               # 服务间调用装配层，一域一模块，一个模块一个自动装配类
    ├── xht-platform-client-blog      #   操作日志上报（Feign → xht-admin），已被 xht-generate 引入
    ├── xht-platform-client-dict      #   字典查询（Feign + Redis 缓存 → xht-admin），预留
    └── xht-platform-client-message   #   站内信发送（Feign → xht-admin），预留
```

> `xht-platform-common` 与 `xht-platform-client` 是**两个不同的层次**：前者只放「被共享的代码」，后者只放「让共享代码跑起来的自动装配」。业务模块永远只依赖前者 + 后者，绝不依赖对方服务的 `*-domain` / `*-infrastructure`。

### 2.2 四层职责（xht-admin / xht-generate 强制）

| 层 | 模块示例 | 只允许放 | 禁止 |
| --- | --- | --- | --- |
| adapter | `xht-admin-adapter` | `controller`、内部 Feign 服务端 `client/*` | 业务逻辑、直接访问 DAO |
| domain | `xht-admin-domain` | `domain/form`、`domain/query`、`domain/response`、`domain/vo`、`enums`、`service`（接口）、常量 | Web **行为性**类型（`@RestController`、`ResponseEntity`）、MyBatis、任何 infrastructure 类 |
| infrastructure | `xht-admin-infrastructure` | `service`（实现）、`dao` + `dao.impl` + `dao.mapper`、`entity`、`converter`、`properties`、`manager` | 被 adapter 之外的模块反向依赖 |
| start | `xht-admin-start` | 启动类、`config`、`application.yml`、`logback-spring.xml` | 业务代码 |

**关键约定**：Service **接口在 domain、实现在 infrastructure**，两侧包名保持一致，**不建 `service.impl` 子包**。

**Web 参数类型的边界**：Service 接口定义在 domain，因此 `MultipartFile`、`HttpServletResponse` 等**方法入参**属于接口签名的一部分，允许出现在 domain（现状：`ISysFileService`、`ILoginService`）。禁止的是让 domain 承载 Web **行为**——不声明 `@RestController` / `@RequestMapping`、不返回 `ResponseEntity`、不依赖 `xht-spring-boot-starter-web`。这类入参由 Controller 原样透传，不在 Controller 侧拆解重组。

### 2.3 依赖方向（单向，禁止反向）

```
start ──► adapter ─────────► domain ──► common(xht-admin-common)
  │                             ▲            ▲
  └──────► infrastructure ──────┘            │
                                             │
调用方 start ──► xht-platform-client-{域} ───┘   # 只依赖 common + Feign，不依赖对方 domain
```

- `adapter → domain`、`infrastructure → domain`、`start → adapter + infrastructure`；
- `domain` 不依赖任何实现层，保证可被其它服务复用；
- `common` 位于依赖链最底层，只依赖 `xht-framework-*`，**禁止依赖任何业务模块**；
- `client` 只依赖 `common` 与 `xht-spring-boot-starter-openfeign`，只能由**调用方**在 `start`（或经 `domain → common` 传递）引入，**禁止被 `domain` / `infrastructure` 依赖**，否则会形成服务调用自身的环；
- 跨服务调用只能通过 `common` 中的 Feign 契约 + `client` 的自动装配，禁止直接依赖其它服务的 `*-domain`。

> 现状说明：`xht-admin-adapter` 通过 `xht-admin-domain` 传递拿到 `xht-admin-common`，所以 `adapter/client/*` 能直接 `implements` 契约接口；`xht-admin-infrastructure` 也显式声明了 `xht-admin-common`。

### 2.4 包结构（以 xht-admin「行政区划」为例）

```
# domain 层
com.xht.platform.area
├── AreaConstant.java                     # 域常量
├── domain
│   ├── form/SysAreaForm.java             # 继承 BasicForm
│   ├── query/SysAreaQuery.java           # 继承 PageBasicQuery
│   └── response/SysAreaResponse.java
├── enums/AreaHasChildEnum.java
└── service/ISysAreaService.java          # 接口

# infrastructure 层
com.xht.platform.area
├── converter/SysAreaConverter.java       # MapStruct
├── dao
│   ├── SysAreaDao.java                   # 仓储接口
│   ├── impl/SysAreaDaoImpl.java          # 继承 MapperRepositoryImpl
│   └── mapper/SysAreaMapper.java         # 继承 BaseMapperX
├── entity/SysAreaEntity.java             # 继承 BasicEntity
└── service/SysAreaServiceImpl.java       # 实现（与接口同包名，不同模块）

# adapter 层
com.xht.platform.controller.area.SysAreaController.java
com.xht.platform.client.dict.SysDictClientImpl.java   # 内部接口实现（实现在 adapter，契约在 common）
```

- `adapter` 下的 `client/{域}` 只放「对外/对内 API 入口」，与 `controller` 平级；它依赖 `common` 的契约接口，不反向被 `common` 依赖；
- Mapper XML 放在 `infrastructure/src/main/resources/mapper/{域}/XxxMapper.xml`，与 `dao.mapper` 包一一对应；`mapper-locations` 统一为 `classpath*:mapper/**/*Mapper.xml`。

### 2.5 包扫描特例

除 `xht-spring-boot-starter-spring-cloud` 的根包为 **`com.xht.cloud`** 外，其余框架模块均以 `com.xht.framework.*` 开头。业务启动类位于 `com.xht.platform`（admin/generate）或 `com.xht.auth`、`com.xht.gateway`，新增组件时注意包路径不要落到扫描范围之外。

### 2.6 模块级公共包 `xht-platform-common`

每个业务服务有一个自己的公共包，**只承载「被多层共享的代码」，不承载任何业务实现**（无 Controller、无 Service 实现、无 DAO、无 Entity）。

```
com.xht.platform.common
├── AdminConstants.java              # 服务名等全局常量（APPLICATION_NAME = "xht-admin"，常量接口风格）
├── {域}                             # dict / message / audit / file / router
│   ├── api/                         # 契约签名 IXxxClient（只有方法，无注解；调用方与服务端共用）
│   ├── domain/                      # 契约 DTO / VO，如 DictVO
│   ├── factory/                     # 对外门面 IXxxFactory（隔离 Feign + 缓存细节）
│   └── core/  bo/  constant/  enums/# 内部模型、BO、常量、枚举
└── ...
```

- `xht-generate-common` 两个常量类分工固定：`GenerateConstants` 只承载服务名，新增生成器业务常量一律进 `GenConstant`（`constant/`）。两个 common 共用 `com.xht.platform.common` 根包（历史未拆包），新增类前确认类名不冲突，新增子包按 `{域}` 划分；
- **硬性依赖约束**：只允许依赖 `xht-framework-core`、`xht-spring-boot-starter-log`；**禁止**引入 `xht-spring-boot-starter-openfeign`、`xht-spring-boot-starter-web`、`xht-spring-boot-starter-mybatis-plus`、任何 `*-domain` / `*-infrastructure`——契约只写签名，注解一律在 client 模块；
- common 内的类不得带业务语义（如「新增用户」），只能是常量、模型、契约、纯工具；common 一旦变更所有依赖方都要回归，因此只允许**追加**，修改已有字段须评估兼容性；
- 两个已存在的结构例外，**不要求回头改造，但新增类不得仿照**：
  - `router` 域：契约模型在 `router/dto`（`RouterDTO`、`RouterMetaDTO`），未按 `domain/` 归位；
  - `message` 域：门面 `IMessagePublisher` 与 `MessagePayloadBuilder` 直接位于 `message` 根包（无独立 `factory/` 子包）。

**放 common 还是放 domain 的判定**：

| 场景 | 归属 |
| --- | --- |
| 两个及以上模块（含其它服务）共用的枚举、常量 | `common` |
| 服务间调用的接口（`IXxxClient`）与其出入参 DTO | `common` 的 `{域}/api` + `{域}/domain` |
| 只有本服务用的 `Form` / `Query` / `Response` / `VO` | `*-domain` |
| Entity / DAO / Converter / Service 实现 | `*-infrastructure` |
| 只有本服务用的纯工具 | 优先 `common` 的 `{域}/utils`，避免在 adapter 与 infrastructure 各写一份 |

> 注意：`@Dict` 字典校验注解与其 `ConstraintValidator` **不在 common，而是随 `xht-platform-client-dict` 提供**（`com.xht.platform.dict.validation`）。原因：校验器强依赖该模块注册的 `ISysDictFactory`，放 common 会变成「编译能过、运行期缺 bean」。因此未引入该模块的服务无法使用 `@Dict`——配置错误前移到编译期。使用要点：值为 `null`/空白时放行，字段必请配合 `@NotBlank`；`disabled = true` 的字典项判定为不合法。

### 2.7 服务间调用装配层 `xht-platform-client`

一域一模块，每个模块**只做三件事**：声明 Feign 客户端子接口（`@FeignClient`）、注册降级工厂、把门面 bean 暴露给业务。不放任何业务逻辑。

| 模块 | 依赖 | 自动装配类 | 暴露给业务的 bean |
| --- | --- | --- | --- |
| `client-blog` | `xht-admin-common` + `xht-spring-boot-starter-log` | `BLogAutoConfiguration` | `BLogRepository`（Feign 上报），仅 `xht.blog.repository-type=feign` 时生效；**已被 `xht-generate` 引入** |
| `client-dict` | `xht-admin-common` + `xht-spring-boot-starter-cache` | `DictAutoConfiguration` | `ISysDictFactory`（内置 Redis 缓存）＋ `@Dict` 校验注解 |
| `client-message` | `xht-admin-common` | `MessageAutoConfiguration` | `IMessagePublisher`（`MessageClientPublisher`） |

装配三件套模板：

```java
@Slf4j
@Configuration(proxyBeanMethods = false)
@EnableFeignClients(clients = SysDictFeignClient.class)      // 精确注册，禁止全包扫描
public class DictAutoConfiguration {

    @Bean
    public SysDictClientFallbackFactory sysDictClientFallbackFactory() {   // 降级工厂显式注册
        return new SysDictClientFallbackFactory();
    }

    @Bean
    public ISysDictFactory sysDictClient() {
        return new SysDictApiFactory();
    }
}
```

并在 `src/main/resources/META-INF/spring/org.springframework.boot.autoconfigure.AutoConfiguration.imports` 写入一行全限定类名。

调用方使用方式：引入 `xht-platform-client-{域}` 依赖后直接注入门面，**不需要**写 `@EnableFeignClients`、不需要配置 `url`。

**硬性约束**：

1. `@EnableFeignClients(clients = ...)` 必须精确列出契约，禁止 `basePackages = "com.xht"` 全包扫描：会把其它服务的契约一并注册成 Feign 代理，也可能与 `contextId` 撞名；
2. `FallbackFactory` 由自动装配类以 `@Bean` 注册（**不要** `@Component` + `@ComponentScan`）：自动装配模块不该依赖调用方的扫描路径，漏扫时启动即失败；
3. 业务只依赖门面接口；确需 `R` 原始结构时才直接注入契约；禁止在 `domain` / `infrastructure` 中注入 `@FeignClient`；
4. **服务提供方要提供本地 `@Primary` 门面实现**，避免「自己 Feign 自己」：如 `xht-admin` 的 `MessageSysPublisher` 标了 `@Primary`；
5. 一个服务对应一个 client 模块，禁止跨服务混装；新增域时新建模块，不往已有模块里塞。

### 2.8 新增代码该放哪里

| 要新增的东西 | 位置 |
| --- | --- |
| 一个后台管理业务域（如「优惠券」） | `xht-admin` 四层各建 `{域}` 包，按 2.2 职责落位，包根 `com.xht.platform.{域}` |
| 只有本服务用的 Form/Query/Response/VO | `xht-admin-domain` 的 `{域}/domain/*` |
| 两个及以上服务共用的枚举、常量、契约 | `xht-platform-common` 对应 common 包 |
| 服务间调用能力 | `common` 写契约签名 → 新建 `xht-platform-client-{域}` 模块装配 → 被调方 `adapter/client/{域}` 写实现 |
| 全局横切能力（异常处理、注解、拦截器） | `xht-framework-parent` 对应 starter，禁止在业务服务里散写 |
| 复杂 SQL 的 Mapper XML | `xht-*-infrastructure/src/main/resources/mapper/{域}/XxxMapper.xml` |
| 数据库脚本 | `doc/sql/`（新表须同步更新初始化脚本） |

## 3. 命名规范（以项目现有写法为准）

### 3.1 包命名

- 全小写，多级用 `.` 分隔，禁止下划线与大写；
- 业务包格式：`com.xht.platform.{业务域}.{层级}`，如 `com.xht.platform.system.dao.mapper`；业务域按**功能**划分（`system`、`dict`、`notice`、`area`、`file`、`oauth2`、`audit`），不按技术分层再套业务；
- 公共包格式：`com.xht.platform.common.{业务域}.{职责}`（`api` / `domain` / `factory` / `validation` / `core` / `bo` / `enums` / `constant` / `utils`）；
- 服务调用装配包格式：`com.xht.platform.{业务域}`，只放 `XxxAutoConfiguration` 与该域的实现适配类。

### 3.2 类命名（后缀固定，不得自创）

| 类型 | 后缀 | 示例 |
| --- | --- | --- |
| 控制器 | `Controller` | `SysAreaController` |
| 服务接口 / 实现 | `I` + `Service` / `ServiceImpl` | `ISysAreaService` / `SysAreaServiceImpl` |
| 仓储接口 / 实现 | `Dao` / `DaoImpl` | `SysAreaDao` / `SysAreaDaoImpl` |
| Mapper | `Mapper` | `SysAreaMapper` |
| 实体 | `Entity` | `SysAreaEntity` |
| 表单 / 查询 | `Form` / `Query` | `SysAreaForm` / `SysAreaQuery` |
| 响应 / 聚合视图 | `Response` / `VO`（大写，禁止 `Vo`） | `SysAreaResponse` / `SysUserVO` |
| 内部业务对象 | `BO`（大写，禁止 `Bo`） | `GenCodeCoreBO` |
| 转换器 | `Converter` | `SysAreaConverter` |
| 服务间契约 / Feign 客户端 | `I` + `Client` / `XxxFeignClient`（承载注解） | `ISysDictClient` / `SysDictFeignClient` |
| 门面 / 降级 | `I` + `Factory` / `Publisher`、`Fallback` / `FallbackFactory` | `ISysDictFactory`、`SysDictClientFallback` |
| 自动装配（client 模块） | `AutoConfiguration` | `DictAutoConfiguration` |
| 配置类 | `Config` / `Properties` | `ThreadPollConfig`、`LoginProperties` |
| 枚举 / 工具类 / 异常 | `Enum`、`Utils` / `Helper`、`Exception` | `AreaHasChildEnum`、`StringUtils`、`CaptchaException` |

**禁止**：`XxxFormRequest`、`XxxQueryRequest`、`XxxDTO` 这类历史命名；实现类带接口前缀（如 `ISysNoticeServiceImpl`）。

> 【不一致点】枚举后缀存在 `Enum` 与 `Enums` 两种（`AreaHasChildEnum` vs `RoleTypeEnums`），**新增枚举统一用 `Enum`**，存量 `Enums` 不强制改名。

### 3.3 方法命名（同类操作跨模块一致）

| 语义 | 命名 | 说明 |
| --- | --- | --- |
| 新增 | `create` | 统一用 `create`，不用 `add`/`insert` |
| 修改 | `updateById` | 需要主键的更新 |
| 删除 | `remove` / `removeById` | 逻辑删除语义也用 `remove` |
| 单查 | `findById` | 返回 `XxxResponse`，查不到返回 `null` 由上层判空 |
| 分页 | `findPageList` / `findXxxPageList` | 按作用域区分时 `findAdminPageList`、`findMyPageList`，禁止 `page` / `selectXxxPage` |
| 列表 | `listByXxx` / `list` | 不分页 |
| 树 | `findTree` / `getDeptTree` | 树形结构 |
| 存在性 | `exists` / `existsXxx` | 返回 `boolean` |
| 校验 | `checkXxx` | 私有校验方法 |

- 布尔返回值以 `is` / `has` / `exists` 开头，禁止 `getIsXxx`；
- 转换方法固定 `toEntity` / `toResponse`，分页转换由 `PageConverter#toResponse(Page)` 提供。

> 【不一致点】删除操作 `remove` 与 `removeById` 并存（`SysAreaController.remove` vs `SysDictController.removeById`），两者均为项目认可写法；同一 Controller 内保持统一即可。

### 3.4 变量与常量

- 局部变量小驼峰，禁止单字母（循环变量 `i`/`j` 除外）；
- 常量全大写下划线分隔，集中放在域常量类（如 `AreaConstant`）或框架 `RConstants`；
- 魔法值一律提常量或枚举，禁止在业务代码里写 `"0"`、`"1"`、`"admin"` 这类字面量；
- 常量类风格：**新增常量类用 `final class` + 私有构造**；存量 `AdminConstants` / `GenerateConstants` 为常量接口风格，不要求回头改造。
  > 【不一致点】常量接口风格 vs final class 风格并存，以「新增不再建常量接口」为准。

### 3.5 数据库命名

| 对象 | 规则 | 示例 |
| --- | --- | --- |
| 表 | 小写下划线，按域加前缀 | `sys_user`、`sys_dict_item`、`gen_table`、`b_log` |
| 字段 | 小写下划线 | `create_time`、`del_flag`、`user_name` |
| 主键 | `id`（bigint 自增或雪花） | `id` |
| 索引 / 唯一索引 | `idx_{表}_{字段}` / `uk_{表}_{字段}` | `idx_sys_user_user_name`、`uk_sys_dict_dict_code` |

- 后台管理域统一 `sys_` 前缀，代码生成域 `gen_` 前缀，框架级日志表 `b_log`；
- 实体类名 = 表名去前缀后的驼峰（`sys_dict_item` ↔ `SysDictItemEntity`），字段名 = 列名驼峰；
- 布尔语义列用 `is_xxx`（tinyint），状态列用 `xxx_status` 并配枚举。

### 3.6 Redis Key

- 统一前缀 `xht:`，格式 `xht:{业务}:{标识}`，如 `xht:dict:{dictCode}`、`xht:rememberMe`；
- Key 前缀由配置驱动（`xht.global.dict.key-prefix`、`xht.security.remember-me.cache-key`），禁止硬编码；
- 必须设置过期时间，永久 Key 需在评审中说明理由。

### 3.7 配置项

- 业务配置统一挂 `xht.` 前缀，按域二级分组：`xht.security.*`、`xht.file.*`、`xht.oauth2.*`、`xht.blog.*`；
- 配置类用 `@ConfigurationProperties(prefix = "xht.xxx")` + `@Validated`，禁止散落的 `@Value`；
- 敏感值（密码、密钥）只允许出现在 Nacos 或环境变量，不进 Git。

## 4. 代码写法规范（分层编码）

### 4.1 Controller

```java
@Tag(name = "行政区划")
@RestController
@RequestMapping("/sys/area")
@RequiredArgsConstructor
public class SysAreaController {

    private final ISysAreaService sysAreaService;

    @BLog(value = "行政区划", description = "添加系统管理-行政区划")
    @Operation(summary = "添加系统管理-行政区划")
    @PostMapping("/create")
    public R<Void> create(@Validated(Groups.Create.class) @RequestBody SysAreaForm form) {
        sysAreaService.create(form);
        return R.ok().build();
    }

    @CheckMenu("sys:area:remove")
    @BLog(value = "行政区划", description = "根据主键`id`删除系统管理-行政区划")
    @Operation(summary = "根据主键`id`删除系统管理-行政区划")
    @PostMapping("/remove/{areaId}")
    public R<Void> remove(@PathVariable Long areaId) {
        sysAreaService.remove(areaId);
        return R.ok().build();
    }
}
```

强制要求：

1. 类上四件套：`@Tag` + `@RestController` + `@RequestMapping` + `@RequiredArgsConstructor`；
2. 依赖注入统一 `private final` 构造器注入（`@RequiredArgsConstructor`），全项目禁止 `@Autowired` 字段注入；
3. 返回值一律 `R<T>`，**禁止**返回裸对象、`ResponseEntity`、`Result`；
4. 写操作加 `@BLog` 与 `@Operation`；需要权限控制的加 `@CheckMenu`；
5. 新增/修改必须带 `@Validated(Groups.Create.class)` / `@Validated(Groups.Update.class)`；
6. Controller 内**不写业务逻辑**，不做转换、不判空兜底，只做参数接收与结果包装。

### 4.2 Service

接口（domain 层）：

```java
public interface ISysAreaService {
    void create(SysAreaForm form);
    void remove(Long areaId);
    void updateById(Long areaId, SysAreaForm form);
    SysAreaResponse findById(Long areaId);
    List<SysAreaResponse> listByParentId(String parentAreaCode);

```

实现（infrastructure 层，与接口同包名）：

```java
@Slf4j
@Service
@RequiredArgsConstructor
public class SysAreaServiceImpl implements ISysAreaService {

    private final SysAreaDao sysAreaDao;
    private final SysAreaConverter sysAreaConverter;

    @Override
    @Transactional(rollbackFor = Exception.class)
    public void create(SysAreaForm form) {
        checkForm(null, form);
        sysAreaDao.save(sysAreaConverter.toEntity(form));
    }

    private void checkForm(Long areaId, SysAreaForm form) {
        AssertUtils.notNull(form, "表单参数不能为空");
        boolean existsAreaCode = sysAreaDao.existsAreaCode(form.getAreaCode(), areaId);
        AssertUtils.isTrue(!existsAreaCode, "区划编码已存在");
    }
}
```

强制要求：

1. 写方法必须 `@Transactional(rollbackFor = Exception.class)`；只读查询不加事务；传播行为默认 `REQUIRED`，确需 `REQUIRES_NEW` 的在注释中说明原因；事务加在 Service 实现方法上，不在 Controller 或 DAO 上开事务；
2. 业务校验统一 `AssertUtils.notNull / isTrue / hasText / notEmpty`（失败抛 `BusinessException`），**禁止** `if (...) throw new RuntimeException(...)`；
3. Service 只依赖本域 DAO 与 Converter；跨域调用走对端 Service 接口，不直接注入其它域 DAO；
4. 返回 `Response`/`VO`，**禁止把 Entity 作为 Service 返回值**；
5. 事务内禁止调用远程服务（Feign）、发送消息、发起 HTTP 请求，必要时通过事件或事务提交后回调。

### 4.3 DAO

```java
public interface SysAreaDao extends MapperRepository<SysAreaEntity> {
    void updateHasChild(String areaCode, AreaHasChildEnum hasChild);
    boolean existsAreaCode(String areaCode, Long id);
}

@Slf4j
@Repository
public class SysAreaDaoImpl extends MapperRepositoryImpl<SysAreaMapper, SysAreaEntity> implements SysAreaDao {

    @Override
    public boolean existsAreaCode(String areaCode, Long id) {
        LambdaQueryWrapper<SysAreaEntity> wrapper = new LambdaQueryWrapper<>();
        wrapper.eq(SysAreaEntity::getAreaCode, areaCode);
        wrapper.ne(condition(id), SysAreaEntity::getId, id);
        return exists(wrapper);
    }

    @Override
    protected SFunction<SysAreaEntity, ?> getFieldId() {
        return SysAreaEntity::getId;
    }
}

@Mapper
public interface SysAreaMapper extends BaseMapperX<SysAreaEntity> {
}
```

强制要求：

1. 仓储接口继承 `MapperRepository`，实现继承 `MapperRepositoryImpl<Mapper, Entity>` 并实现 `getFieldId()`；
2. Mapper 必须继承 `BaseMapperX`，**禁止**直接继承原生 `BaseMapper`；
3. 条件用 `LambdaQueryWrapper` / `LambdaUpdateWrapper`，字段引用一律方法引用（`SysAreaEntity::getAreaCode`），禁止字符串列名；条件拼接使用基类 `condition(...)`，避免 `if` 堆叠；
4. 单表 CRUD 不写 XML；复杂多表查询才写 XML（见 7 章 SQL 规则）；
5. DAO 方法不返回 `null` 语义的集合，统一返回空集合。

### 4.4 Converter

```java
@Mapper(componentModel = MappingConstants.ComponentModel.SPRING,
        unmappedTargetPolicy = ReportingPolicy.IGNORE)
public interface SysAreaConverter extends PageConverter<SysAreaEntity, SysAreaResponse> {
    SysAreaEntity toEntity(SysAreaForm form);
}
```

强制要求：

1. 必须 `componentModel = SPRING`，构造器注入使用，**禁止 `Mappers.getMapper()`**；
2. 涉及分页转换的继承 `PageConverter<Entity, Response>`，直接调用 `toResponse(Page<Entity>)`；
3. 字段名不一致、需要类型转换时显式写 `@Mapping`，禁止依赖隐式约定；
4. 复杂拼装（跨表、跨服务）放在 Service 私有方法或专用 `Helper`，不要塞进 Converter。

### 4.5 Entity

```java
@Data
@EqualsAndHashCode(callSuper = true)
@TableName("sys_area")
public class SysAreaEntity extends BasicEntity {

    @TableId(type = IdType.AUTO)
    private Long id;
```

| 基类 | 字段 | 适用场景 |
| --- | --- | --- |
| `BasicEntity` | `createTime`、`updateTime`、`createBy`、`updateBy`、`delFlag` | 默认选择 |
| `DeleteEntity` | `delFlag` | 无需审计但需逻辑删除 |
| `NoneDeleteEntity` | 审计字段，无 `delFlag` | 物理删除表（如日志、关联表） |

强制要求：

1. 必须显式 `@TableName`；
2. 审计字段与 `delFlag` 由 `MetaObjectHandler` 自动填充，**业务代码禁止手动 set**（`createBy` 填的是 `username` 而非 userId）；
3. 主键统一 `Long id` + `@TableId`，禁止在业务代码里假设自增/雪花；
4. Entity 只在 infrastructure 内部流转，不出现在 Controller、Response、Feign 契约中。

### 4.6 日志

- 统一 `@Slf4j` + 占位符 `log.info("查询用户, userId: {}", userId)`；禁止 `System.out.println`、字符串拼接、自建 `LoggerFactory`；
- 级别约定：`ERROR` 仅用于需要人工介入的失败；`WARN` 用于可恢复异常与降级；`INFO` 记录关键业务流转；`DEBUG` 调试细节，生产默认关闭；
- 异常日志必须带堆栈：`log.error("保存用户失败, userId: {}", userId, e)`；禁止 `e.printStackTrace()`、空 catch；
- 禁止在日志中输出密码、令牌、身份证、手机号全量等敏感信息（见第 9.4 节）。

操作日志 `@BLog`：

```java
@BLog(value = "用户管理", description = "重置用户密码")
@PostMapping("/reset/{userId}/pwd")
public R<Void> resetPassword(@PathVariable Long userId) { ... }
```

- `value` 与 `description` 均必填，`value` 用模块名，`description` 用「动作 + 对象」；写在 Controller 写操作上；
- 切面自动采集操作人、IP、请求参数（自动过滤 `HttpServletRequest`、`MultipartFile`）、耗时、`traceId`、异常；
- 落库方式由 `xht.blog.repository-type` 决定：`default` 仅 `log.debug` 输出（**不落库**）、`feign` 上报 `xht-admin`、`jdbc` 本地直写（**仅 `xht-admin` 提供该实现**，其它服务配 `jdbc` 会因缺 Bean 静默失效）；生产环境必须显式配置；
- `b_log` 表必须含 `title`、`log_desc` 两列，缺列时异常被切面吞掉，表现为「一条日志都没有」；
- Feign 上报是**同步**调用（切面在 `finally` 内执行），必须配短超时（如 `connect-timeout: 1000` / `read-timeout: 2000`），否则 admin 不可达时阻塞业务线程；
- 保存失败只记录 error 不影响主流程，不要依赖该日志做审计对账。

### 4.7 链路追踪

- `traceId` 由网关/过滤器生成，写入 MDC，`R.traceId` 自动回填；跨服务由 `xht-spring-boot-starter-openfeign` 拦截器透传；
- 异步线程需手动传递 MDC 上下文（参考 `ThreadPollConfig` 的线程池装饰），否则日志丢失 `traceId`。

### 4.8 缓存

```java
private final RedisRepository redisRepository;
```

- 统一使用 `RedisRepository`（`xht-spring-boot-starter-cache`），**禁止直接注入 `RedisTemplate` 做业务缓存**；
- Key 规范见 3.6，读写必须显式指定过期时间；
- 缓存更新策略：**先更新库、再删缓存**；禁止「先删缓存再写库」；
- 缓存穿透：空结果缓存短 TTL；缓存击穿：热点 Key 加互斥锁或逻辑过期；
- 字典等低频变更数据可全量缓存，用户/权限类数据必须按维度 Key 缓存并支持主动失效。

### 4.9 当前登录用户上下文

统一通过 `com.xht.framework.oauth2.utils.SecurityUtils` 获取，**禁止业务代码直接读 `SecurityContextHolder`**。

| 方法 | 返回 | 语义 |
| --- | --- | --- |
| `getAuthentication()` | `Optional<Authentication>` | 匿名请求返回 `Optional.empty()`，用于「可能未登录」场景 |
| `isLogin()` | `boolean` | 是否已登录；匿名请求为 `false` |
| `getUser()` | `BasicUserDetails` | 未登录或 principal 不符时抛 `BasicAuthenticationException` |
| `getUserId()` / `getUserName()` / `isAdmin()` | — | 等价 `getUser()` 的快捷方法；`getUserName()` 是登录账号不是昵称 |

`BasicUserDetails` 可直接取：`userId`/`username`/`nickName`、`userType`、`userStatus`、`deptId`/`deptName`（数据权限过滤）、`roleCodes`（配合 `@CheckRole`）、`menuButtonCodes`、`userPhone`/`loginType`，无需再查库。

硬性约束：

1. 只有在**必然已登录**的接口里才能直接调用 `getUserId()` 等；`@IgnoreAuth` 接口、定时任务、MQ 消费者、异步线程必须先 `isLogin()` 或 `getAuthentication()` 判断；
2. 异步场景在提交任务前把 `userId`、`userName` 作为参数传入（`SecurityContext` 基于 ThreadLocal）；
3. 「可能为空」的用户信息用 `getAuthentication().map(...)` Optional 链，不要 try-catch 吞异常。

## 5. 接口请求规范

### 5.1 路径风格：动词式，非纯 RESTful

本项目**不采用纯 RESTful 风格**，统一「资源前缀 + 动作」的动词式路径。这是当前全部 23 个 Controller、127 个端点的实际写法（`xht-admin` 16 个 / 93 个，`xht-generate` 7 个 / 34 个；`adapter/client/*` 的 3 个内部 Feign 服务端端点不计入），新增接口必须保持一致。

| 操作 | HTTP 方法 | 路径模式 | 示例 |
| --- | --- | --- | --- |
| 新增 | POST | `{前缀}/create` | `POST /sys/area/create` |
| 修改 | POST | `{前缀}/update/{id}` | `POST /sys/area/update/{areaId}` |
| 删除 | POST | `{前缀}/remove/{id}` | `POST /sys/area/remove/{areaId}` |
| 详情 | GET | `{前缀}/get/{id}` | `GET /sys/area/get/{areaId}` |
| 分页 | POST | `{前缀}/page`（JSON body） | `POST /sys/user/page`，body `{"current":1,"size":10}` |
| 列表 / 树 | GET | `{前缀}/list`、`{前缀}/list/{父级}`、`{前缀}/tree` | `GET /sys/area/list/{parentAreaCode}`、`GET /sys/menu/tree` |
| 状态变更 | POST | `{前缀}/updateStatus/{id}/{status}` | `POST /sys/role/updateStatus/{roleId}/{roleStatus}` |
| 业务动作 | POST | `{前缀}/{动作}/{id}` | `POST /sys/notice/publish/{noticeId}` |

资源前缀规则：

- 后台管理：`/sys/{资源}`，二级资源嵌套（`/sys/dict/item`、`/sys/notice/type`、`/sys/user/role`）；
- 代码生成：`/gen/{资源}`，二级嵌套（`/gen/table/info`、`/gen/template/group`）；
- 内部服务接口：`/api/{原前缀}`（如 `/api/sys/dict`），只允许服务间调用；
- 登录相关：`/login/form`、`/login/phone`。

硬性约束：

1. **写操作一律 POST**，禁止 PUT / DELETE / PATCH；
2. 同一资源只保留一种动作写法，不允许同时存在 `/create` 与 `/add`；
3. 路径段小写，不出现下划线；确需驼峰动作（`underShelve`、`syncTable`）时全项目统一并评审确认；
4. 网关访问加服务前缀：`/admin/sys/area/create`、`/generate/gen/code/view`（`StripPrefix=1`）。

> 演进方向（说明，非强制）：后续若统一为 RESTful，需一次性完成「Controller + 前端 API + 网关 + 文档 + 权限码」同步改造，禁止新旧风格长期并存。当前阶段以本节为准。

### 5.2 请求参数与校验

```java
public class SysAreaForm extends BasicForm {
    @NotEmpty(message = "区划编码参数不合法", groups = {Groups.Create.class, Groups.Update.class})
    @Schema(description = "区划编码")
    private String areaCode;
}
```

- 提交对象继承 `BasicForm`，查询对象继承 `PageBasicQuery`（分页）或 `BasicQuery`；
- 校验注解必须带 `groups`，由 Controller 的 `@Validated(Groups.Xxx.class)` 触发；统一 `jakarta.validation`，禁止 `javax.validation`；
- 每个字段必须有 `@Schema(description = "...")`，否则文档不可读。

### 5.3 分页

```java
@Operation(summary = "分页查询系统用户")
@PostMapping("/page")
public R<PageResponse<SysUserResponse>> findPageList(@RequestBody SysUserQuery query) {
    return R.ok().build(sysUserService.findPageList(query));
}
```

- 入参统一 `@RequestBody` JSON（`Content-Type: application/json`），不用 query string 传分页与筛选；GET 仅用于详情、列表、树等不分页查询；
- body 为空返回 400，无筛选条件时也要传 `{}`；
- `LocalDateTime` 按全局反序列化器传 `yyyy-MM-dd HH:mm:ss`，不传 ISO 的 `T` 格式；
- 枚举筛选字段优先传枚举值（以各枚举 `@JsonValue` 为准）；
- 分页字段固定 `current` / `size`（来自 `PageBasicQuery`），**不是** `pageNum` / `pageSize`；分页作用域用路径区分（`/admin/page`、`/my/page`），不加额外参数；
- Service 内部通过 `PageTool.getPage(query)` 构造 `Page`，DAO 返回 `Page<Entity>`，Converter 转 `PageResponse<Response>`。

### 5.4 统一响应体 `R<T>`（禁止裸对象 / `ResponseEntity` / 自造 `Result`）

`com.xht.framework.common.domain.R<T>`：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `code` | Integer | 业务码，**不是** HTTP 状态码；`200` 成功、`500` 失败 |
| `msg` | String | 提示信息（**字段名是 `msg`，不是 `message`**） |
| `data` | T | 业务数据 |
| `dataType` | DataTypeEnum | `NORMAL` / `ENCRYPT` |
| `traceId` | String | 链路追踪 ID |

```json
{ "code": 200, "msg": "成功！", "data": { }, "dataType": "NORMAL", "traceId": "b7f1c0e2a9d34f56" }
```

构造方式（禁止 `new R<>()`）：

```java
R.ok().build();               // 无数据
R.ok().build(data);           // 带数据
R.error(errorCode).build();   // 指定错误码
R.ok().encrypt().build(data); // 响应体加密
```

分页返回 `R<PageResponse<T>>`（`current`/`size`/`pages`/`total`/`records`），4 个 long 字段经 `CustomLongSerializer` 序列化为字符串防前端精度丢失，前端按字符串或数值双兼容处理，**后端不要改序列化器**。

### 5.5 错误码与异常

```java
public interface ErrorCode {
    int getCode();
    String getMessage();
}
```

- 每个业务域定义自己的错误码枚举（如 `SysUserErrorCode`），实现 `ErrorCode`；
- 错误码分段：`sys` 域 1xxxx、`gen` 域 2xxxx、认证 3xxxx，分段由模块负责人维护；
- **禁止**硬编码错误码数字，禁止 `new BusinessException("xxx")` 直接传业务提示（文案来自枚举，自定义文案仅用于补充上下文）。

| 场景 | 做法 |
| --- | --- |
| 参数/业务规则校验 | `AssertUtils.notNull / isTrue / hasText / notEmpty` |
| 明确的业务错误 | `throw new BusinessException(ErrorCode)` |
| 需要自定义文案 | `throw new BusinessException(ErrorCode, "自定义提示")` |
| 包装底层异常 | `throw new BusinessException(ErrorCode, e)`，保留堆栈 |
| 不可恢复的编程错误 | 直接抛运行时异常，交由全局处理器兜底 |

- 全局异常由 `xht-spring-boot-starter-web` 的 `DefaultGlobalExceptionHandler` 统一兜底，**Controller 不写 try-catch 拼 `R.error()`**，不吞异常；
- 确需扩展时新增 `@RestControllerAdvice` 并设置更高 `@Order`，只处理自有异常类型。

### 5.6 权限注解

| 注解 | 来源 | 语义 | 使用位置 |
| --- | --- | --- | --- |
| `@CheckMenu("sys:area:remove")` | `xht-resource-server` | 校验菜单/按钮权限码，支持逗号分隔多值 | 方法 |
| `@CheckRole("admin")` | `xht-resource-server` | 校验角色编码 | 方法 |
| `@IsAdmin` | `xht-resource-server` | 仅管理员可访问 | 方法 |
| `@IgnoreAuth` | `xht-security` | 免鉴权：加白名单；方法级（含契约接口方法）按 `aop` 决定是否校验内部调用头 | 类 / 方法 |

权限码命名：`{模块}:{资源}:{动作}`，如 `sys:user:create`、`sys:role:menu:bind`，与前端菜单按钮配置保持一致。

注意事项：

1. `@CheckMenu` / `@CheckRole` / `@IsAdmin` 依赖 `@EnableResourceServer` 开启的方法级安全；
2. `@IgnoreAuth` 标在**类**上只进白名单，不触发内部头校验；需要内部调用校验的必须标在**方法**上；
3. 方法级注解**支持从契约接口继承**：`XxxClientImpl` 漏标时框架仍按接口方法上的注解校验；实现类显式重复标注便于阅读，是推荐写法；
4. 对外开放接口用 `@IgnoreAuth(aop = false)` 显式关闭内部头校验；
5. 同一 Controller 中**直接同时**声明类级与方法级 `@IgnoreAuth` 会启动期抛异常；若方法注解继承自接口、类上又声明了注解，只打告警不阻断启动。

### 5.7 文档注解

- 类：`@Tag(name = "行政区划")`；方法：`@Operation(summary = "...")`；字段：`@Schema(description = "...", example = "...")`；
- Swagger starter 的自动装配清单为空，启动类必须标注 `@EnableCustomSwagger`，否则没有文档端点。

### 5.8 内部服务接口配对

```java
// common 中的契约签名（调用方与服务端共用，不带 Feign / Web 注解）
public interface ISysDictClient {
    R<List<DictVO>> getByDictCode(String dictCode);
}

// client-dict 中的 Feign 客户端（注解与路径只在调用方这一侧）
@FeignClient(name = AdminConstants.APPLICATION_NAME, contextId = "iSysDictClient",
             path = "/api/sys/dict", fallbackFactory = SysDictClientFallbackFactory.class)
public interface SysDictFeignClient extends ISysDictClient {
    @Override
    @FeignIgnoreAuth                          // 内部接口：调用时自动补内部调用头
    @GetMapping("/code/{dictCode}")
    R<List<DictVO>> getByDictCode(@PathVariable("dictCode") String dictCode);
}

// adapter 中的服务端实现
@RestController
@RequestMapping("/api/sys/dict")
@RequiredArgsConstructor
public class SysDictClientImpl implements ISysDictClient {

    private final ISysDictItemService sysDictItemService;

    @Override
    @IgnoreAuth                              // 内部接口，校验内部调用头；实现类建议显式标注
    @GetMapping("/code/{dictCode}")
    public R<List<DictVO>> getByDictCode(@PathVariable String dictCode) {
        return R.ok().build(sysDictItemService.getByDictCode(dictCode));
    }
}
```

`@IgnoreAuth` 与 `@FeignIgnoreAuth` 配对表：

| 服务端 `@IgnoreAuth` | 调用方 `@FeignIgnoreAuth` | 效果 | 现有例子 |
| --- | --- | --- | --- |
| `aop = false` | 不需要 | 白名单放行，且**不校验**内部调用头 | `QrLoginController`（对外公开接口） |
| `aop = true`（默认） | 必须标注 | 白名单放行，但**校验** `auth-key/auth-value`；`auth-value` 未配置时一律拒绝（fail-closed） | `SysDictClientImpl` ↔ `ISysDictClient` 等 3 对 |

- 契约接口与 DTO 放 `common`；**服务端不引 client 模块**，而是让 `adapter` 直接 `implements` 契约，一份接口同时承担「Feign 描述」和「Spring MVC 映射」；
- 服务端实现放 `adapter` 的 `client/{域}/XxxClientImpl`，`@RequestMapping` 与契约 `path` 保持一致；
- 内部接口不对外暴露：网关已关闭 `discovery.locator`，并基于**入站原始路径**拒绝内部根路径（`InternalApiGuardFilter`，返回 404 而非 403，含 `%2e%2e`、`%252e%252e` 等编码变体），只能服务间 Feign 直连；受保护根路径由 `xht.gateway.internal-api.roots` 配置（默认 `["/api"]`），**修改后需重启网关**。

## 6. 组件开发规范（可复用能力：starter / Client 装配 / 公共类）

> 本仓库为纯后端项目，无前端组件（前端在独立仓库 `xht-platform-admin`）。本章「组件」指项目内三类可复用单元。

### 6.1 自研 starter（`xht-framework-parent`）

- 命名统一为 `xht-spring-boot-starter-{能力}`（与 Spring Boot 官方 `spring-boot-starter-{模块}` 对齐，避免与官方前缀冲突）；
  - 正确：`xht-spring-boot-starter-cache`；错误：`xht-cache-spring-boot-starter`；
  - Spring Cloud 相关也统一用 `xht-spring-boot-starter-spring-cloud`；
  - 非 starter 普通模块不加后缀：`xht-framework-core`、`xht-framework-dependencies`；
- 自动装配走 `META-INF/spring/org.springframework.boot.autoconfigure.AutoConfiguration.imports`（一行全限定类名）；
- 配置属性类统一 `@ConfigurationProperties(prefix = "xht.xxx")` + `@Validated`。

### 6.2 Client 装配模块

见 2.7。补充依赖与降级规则：

- pom 依赖模板：`xht-admin-common` + `xht-spring-boot-starter-openfeign`（+ 需要的 `xht-spring-boot-starter-cache`）；
- 降级类继承 `BasicFallback`，实现 **Feign 子接口**（不是 common 签名接口），泛型写 `FallbackFactory<XxxFeignClient>`：

```java
public class SysDictClientFallback extends BasicFallback implements SysDictFeignClient {

    public SysDictClientFallback(Throwable cause) { super(cause); }

    @Override
    public R<List<DictVO>> getByDictCode(String dictCode) {
        return error();          // 继承自 BasicFallback，等价 R.error().msg(cause.getMessage())
    }
}
```

- 用 `error()` / `error(msg)` 返回 `R.error()`，**不要直接 `return null`**；
- 若降级类只实现父接口（`IXxxClient`），降级触发时 `Method.invoke` 会因不是 Feign 子接口实例而失败、异常被框架吞掉后返回 `null`——必须实现子接口；
- 降级只负责「给出可判定的失败结果」，是否兜底默认值由调用方决定；
- **降级的前提**：`fallback`/`fallbackFactory` 只在开启熔断后才参与调用，需要同时配置 `spring.cloud.openfeign.circuitbreaker.enabled=true` 并引入熔断实现（如 resilience4j）。两者缺一，工厂只是装配到位、**不会生效**，Feign 异常直接抛给调用方。**当前仓库尚未开启**，评估降级效果时不要以「配了 fallback」为准。

### 6.3 门面（可选但推荐）

Feign 契约描述「怎么调」，门面描述「业务怎么用」。带缓存、带默认值、需要多接口聚合时，在 `common` 的 `{域}/factory` 定义 `IXxxFactory`，由 client 模块提供实现：

```java
public class SysDictApiFactory implements ISysDictFactory {   // client-dict 中
    @Override
    public List<DictVO> getDictList(String dictCode) {
        return redisRepository.getSet(cacheKey, timeout, unit,
                () -> ROptional.of(sysDictClient.getByDictCode(dictCode)).get().orElse(Collections.emptyList()));
    }
}
```

- 业务只注入 `ISysDictFactory` / `IMessagePublisher`，不感知 Feign；
- 服务提供方（`xht-admin`）自己用同一门面时，提供 `@Primary` 本地实现（`MessageSysPublisher`），避免自调用绕一圈网络。

### 6.4 调用方处理返回值

```java
R<List<DictVO>> resp = sysDictClient.getByDictCode(dictCode);
List<DictVO> list = ROptional.of(resp).get().orElse(Collections.emptyList());
```

- `ROptional.of(r).get()` 成功返回 `Optional<T>`，`code != 200` 时抛 `BusinessException("data is error!")`；
- 因此**降级不等于「自动拿到空集合」**：调用方要么用 `ROptional` 并接受异常，要么显式 `if (!Objects.equals(resp.getCode(), RConstants.SUCCESS))` 处理；
- **禁止** `resp.getData().forEach(...)` 这类不判空写法。

### 6.5 消息（站内信）

- 统一通过 `IMessagePublisher#publish(topic, payload)` 发布：调用方引 `client-message`（Feign → `/api/sys/message/send`）；`xht-admin` 自身注入 `@Primary` 的 `MessageSysPublisher`，直连 Service 不走网络；
- 消息体必须用 `MessagePayloadBuilder` 构造，禁止手拼 `Map` 或 `new MessagePayload(...)`：

```java
MessagePayload payload = MessagePayloadBuilder.builder()
        .sender(sender)                                     // MessageUser
        .recipient(recipient)                               // 可多次调用，支持 List 批量
        .messageType(MessageTypeEnum.SYSTEM_NOTICE)         // 1-系统通知 / 2-业务提醒
        .messageTitle("导出任务已完成")
        .messageContent("文件「{fileName}」已生成")          // 支持占位符
        .build(extendInfo);                                 // MessageExtendInfo 提供占位符数据与跳转地址
```

- `sender`、`recipient`、`messageType`、`messageTitle`、`messageContent` 缺一即抛 `UtilException`，构造后不要再补 set；
- 消息发送失败必须记录日志并保留业务数据，不做「发消息失败就回滚业务」的强耦合设计（除非业务明确要求）；
- 新增消息类型先扩展 `MessageTypeEnum`，并在 `xht-admin` 侧确认站内信列表的展示与筛选逻辑。

### 6.6 文件

| 配置 | 说明 |
| --- | --- |
| `xht.file.storage.type` | `local` 或扩展实现 |
| `xht.file.storage.local.base-path` | 本地存储根目录 |
| `xht.file.upload.max-size` | 服务端权威大小限制，需小于 `spring.servlet.multipart.max-file-size` |
| `xht.file.upload.allowed-suffixes` | 后缀白名单，新增类型需评审 |
| `xht.file.clean.*` | 孤儿文件清理 |

- 上传/下载统一走 `SysFileController`（`POST /sys/files/upload`、`GET /sys/files/download/{fileStorageKey}`，均 `@IsAdmin`），业务入口为 `ISysFileService`，底层存储操作统一收敛到 `FileStorageDao`；旧的 `IFileStorageService`、`FileStorageController` 已删除，禁止再引用；
- 上传必须显式指定上传用户 `UploadBO#fileUploadUser`（空值抛 `FILE_UPLOAD_USER_ILLEGAL`）；文件支持业务解关联（解关联后标记状态并记录时间）；
- 上传必须校验后缀 + 实际文件类型（`FileTypeDetectUtils`），不只信 `Content-Type`；
- 文件名使用存储 Key，禁止用原始文件名拼接路径，防止路径穿越；
- 下载按存储 Key 查 `sys_file` 记录（不存在抛 `FILE_NOT_EXIST`），经 `XhtFileUtils.writeFile` 写出响应并携带原始文件名，失败抛 `FILE_DOWNLOAD_FAIL`；下载/预览校验文件归属，禁止仅凭 Key 直接放行；
- 在线预览分两步：先 `POST /sys/files/preview/init?fileStorageKey=`（入参只有文件存储Key）拿预览初始化信息（`fullOriginalFilename`、`fileSize`、`fileSizeInfo`、`fileType`、`fileSuffix`、`fileStorageName`、`previewUrl`、`downloadUrl`），再按 `previewUrl`（`GET /sys/files/preview`，支持 Range，`Content-Disposition: inline`）取字节流由前端自渲染；不支持预览的格式抛 `FILE_PREVIEW_NOT_SUPPORT`；
- 预览初始化的权限校验收敛在 `SysFileServiceImpl#checkPreviewPermission`：文件用途取自 `sys_file` 记录（调用方不传用途），当前不限制，后续按用途细分授权规则只改该方法，接口契约不变；校验失败抛 `FILE_ACCESS_DENIED`。接口路径常量统一在 `com.xht.platform.file.FileConstant`，Controller 映射与返回的访问地址共用同一份。

### 6.7 数据访问与 SQL 规则

1. **MyBatis-Plus 优先**：单表 CRUD 全部走 `CrudRepository` / `BaseMapperX`，不写 XML；
2. **禁止 `SELECT *`**：XML 显式列出字段，避免表结构变更导致映射错乱；
3. 参数一律 `#{}`，禁止 `${}` 拼接（排序字段等必须走白名单校验，参考 `AscName`/`DescName`）；
4. 分页统一走 MP 分页插件，禁止手写 `LIMIT`；
5. 批量操作使用基类 `saveAll`（默认批 100）与 `IN` 查询分批（1000）；
6. **逻辑删除**：`DELETE` 由 MP 自动改写为 `UPDATE ... SET del_flag=1`；**自定义 XML 查询必须自行追加 `del_flag = 0`**；
7. 逻辑删除表的唯一索引需评估冲突风险（删除后重建同名数据会命中唯一键），建议唯一索引包含 `del_flag` 或改用业务唯一校验；
8. 多表关联超过 3 张表时，优先拆成多次单表查询在 Service 内组装；
9. 新增/变更表结构必须同步更新 `doc/sql` 初始化脚本，并在 PR 中说明。

## 7. Git / 提交规范

### 7.1 提交格式

```
类型: 描述
```

（中文描述，动词开头，不超过 50 字）

| 类型 | 用途 |
| --- | --- |
| `feat` | 新增功能 |
| `fix` | 修复缺陷 |
| `refactor` | 重构（不改行为） |
| `docs` | 文档 |
| `style` | 格式（不影响逻辑） |
| `test` | 测试 |
| `chore` | 构建、依赖、配置 |

- 一次提交只做一件事，避免「顺手格式化」；
- 提交前确保 `mvn -q -DskipTests compile` 通过；PR 前 `mvn test` 不新增失败用例。
- 【不一致点】规范为 `类型: 描述`，但近期实际提交多为 `类型(scope): 描述`（如 `refactor(file): 简化文件存储控制器`）。两种均为可接受格式，**推荐带 scope**以便追溯；【待团队统一】是否把 scope 写入正式规范。

### 7.2 分支模型

- 规范分支模型：`develop` 集成 → `feature/xxx` 功能分支（从 develop 拉出）→ `bugfix/xxx` 修复分支 → `release/x.y.z` 发布准备 → 合入稳定分支打 tag `vX.Y.Z` → 回合 develop；
- 【不一致点】原指南写稳定分支为 `main`，仓库实际远端主分支为 **`master`**（`origin/HEAD -> master`），当前工作分支 `develop`。【待团队统一】稳定分支名以仓库实际为准（`master`），原指南待修订。

### 7.3 版本发布

1. 从 `develop` 创建 `release/x.y.z`；2. release 分支完成测试与修复，版本号语义化；3. 合并到稳定分支并打 tag（`vX.Y.Z`）；4. 回合到 `develop`；5. 同步更新本文档「更新日期」。

### 7.4 测试

- 新增 Converter：覆盖 `toEntity`、`toResponse`、空值场景；
- 新增 Service 校验分支：覆盖「不存在」「重复」「无权限」等失败路径，断言异常码与文案；
- 新增 Controller：至少一个 MockMvc 用例验证参数校验与 `R` 结构；
- 测试类命名 `XxxTest`，与被测类同包；测试数据禁止依赖生产库，使用独立 schema 或 H2；
- `mvn -q test` 必须全绿才可提交 PR。

> 存量现状（2026-10-26 核对）：3 个测试类、11 个 `@Test`、MockMvc 用例 **0** 个，覆盖集中在 `file` / `blog` / `dict`。上述三条对**新增与改动**的代码强制，存量接口按改动触达逐步补齐，不安排集中补测；补测优先覆盖校验分支、权限注解与 `R` 结构。
>
> 存量测试若存在失败用例，以「不新增失败用例」为准，不得以存量失败为由跳过本地测试；相关行为的修正按业务需求安排，不作强制要求。

## 8. 新增功能开发流程

### 8.1 新增业务域的 12 步（以后台新增一个业务域为例）

1. **建表**：`doc/sql` 新增建表脚本，表名加域前缀，含 `create_time`/`update_time`/`create_by`/`update_by`/`del_flag`；
2. **domain/form**：新增 `XxxForm extends BasicForm`，字段加 `@Schema` 与分组校验；
3. **domain/query**：新增 `XxxQuery extends PageBasicQuery`（无需分页则继承 `BasicQuery`）；
4. **domain/response**：新增 `XxxResponse`，只暴露必要字段，敏感字段脱敏；
5. **infrastructure/entity**：新增 `XxxEntity extends BasicEntity`，显式 `@TableName`；
6. **infrastructure/dao**：`XxxDao extends MapperRepository`、`XxxDaoImpl extends MapperRepositoryImpl`、`XxxMapper extends BaseMapperX`，实现 `getFieldId()`；
7. **infrastructure/converter**：`XxxConverter extends PageConverter<XxxEntity, XxxResponse>`，补 `toEntity`；
8. **domain/service**：定义 `IXxxService`，方法按 `create/remove/updateById/findById/findPageList` 命名；
9. **infrastructure/service**：`XxxServiceImpl` 实现（与接口同包名），写方法加事务，校验用 `AssertUtils`；
10. **adapter/controller**：`XxxController`，路径 `/{sys|gen}/{资源}`，写操作 POST + `@BLog` + `@Operation`，按需加 `@CheckMenu`；
11. **权限与菜单**：菜单表配置权限码（`sys:xxx:create` 等）并绑定角色，前端同步按钮权限；
12. **验证**：本地联调（启动顺序 auth(9000) → admin(8081) → gateway(8080)，hosts 配 `127.0.0.1 www.xht.com / www.xht.sso.com`），确认 `/doc.html` 可见、分页与校验生效、操作日志有记录；补单测，按第 7 章规范提交 PR。

> 若该模块的能力需要被其它服务调用，继续按 8.2 的 7 步补契约、降级、client 模块与装配清单，不要直接把 `*-domain` 暴露出去。

### 8.2 新增一个服务间调用的 7 步

1. 在 `common` 的 `{域}/api` 定义 `IXxxClient` —— **只写方法签名**，不带任何 Feign / Web 注解，服务端与调用方共用；
2. 在 `{域}/domain` 新增出入参 `XxxDTO` / `XxxVO`；
3. 新建 `xht-platform-client-{域}` 模块：pom 依赖 `xht-admin-common` + `xht-spring-boot-starter-openfeign`（+ 需要的 `xht-spring-boot-starter-cache`）；
4. 在该模块 `client/` 下写 `XxxFeignClient extends IXxxClient`，承载 `@FeignClient`、`@GetMapping`、`@FeignIgnoreAuth`，方法注解必须重声明；在 `client/fallback`、`client/factory` 补降级类（工厂**不用** `@Component`）；
5. 写自动装配类：`@EnableFeignClients(clients = XxxFeignClient.class)`、`@Bean` 注册降级工厂与门面实现，并写入 `AutoConfiguration.imports`；
6. 被调方 `adapter` 的 `client/{域}` 新增 `XxxClientImpl implements IXxxClient`（实现 common 的签名接口），`@RequestMapping` 与 `path` 一致，标注 `@IgnoreAuth`（按 5.8 配对表决定 `aop`）；
7. 在根 `pom.xml` 的 `<dependencyManagement>` 与 `<modules>` 中登记新模块；调用方 `start` 引入 `xht-platform-client-{域}`，注入门面或契约，按 6.4 处理返回值。

> 若调用方只需要「日志落库」「站内信」这类既有能力，直接引 `xht-platform-client-blog` / `-message` 即可，不要重复造契约。

通用约束：

- Feign 调用**不放在事务内**，也不要在 `@Transactional` 方法尾部顺手调用；必要时改用事务提交后事件；
- 超时、重试按接口特性在 Nacos 中单独配置，禁止全局一刀切；
- 一个契约对应一个 `contextId`，一个服务对应一个 client 模块，禁止「一个大客户端」包打所有服务。

## 9. 禁止事项 & 踩坑提醒

### 9.1 结构红线

1. **不要改四层依赖方向**：domain 不得依赖 infrastructure；Entity 不得出现在 Controller / Response / Feign 契约中；
2. **不要动 `xht-framework-parent` 底层能力**（`R`、异常体系、`BaseMapperX`、`MetaObjectHandler`、`DefaultGlobalExceptionHandler`）——影响所有服务，改动必须单独评审；业务服务**不要**重复定义全局 `@RestControllerAdvice`；
3. **不要在 `xht-platform-common` 引入 Web / Feign / MyBatis 依赖**，契约签名接口禁止带任何注解；common 只允许追加，不破坏兼容；
4. **不要直接依赖其它服务的 `*-domain` / `*-infrastructure`**，跨服务只走 common 契约 + client 装配；`client` 模块禁止被 `domain` / `infrastructure` 依赖。

### 9.2 安全红线

5. **密钥外置**：内部头 `auth-value` 由环境变量 `XHT_SECURITY_AUTH_VALUE` 注入（`xht.security.header.auth-value: ${XHT_SECURITY_AUTH_VALUE:}`），仓库不存明文；`xht-admin`、`xht-auth`、`xht-generate` 必须注入**同一个**值，缺失时 `aop = true` 的内部接口一律拒绝（fail-closed，不依赖「双方都为 null 视为相等」的旧行为），表现为服务间调用 403。数据库密码、Redis 密码、`client-secret` 目前仍为明文示例值，新环境必须替换，禁止带入生产；
6. **越权防护**：所有按 ID 操作的接口必须校验数据归属（当前用户/当前租户/部门范围），不能只校验「已登录」；
7. **`@IgnoreAuth` 管控**：新增免鉴权接口需在 PR 中单独说明，禁止为「联调方便」放开；开放接口用 `aop = false`，内部接口保持 `aop = true`；
8. **注入防护**：SQL 一律参数绑定；XML 中动态排序字段必须白名单校验；`XSS`：`xht.security.xss.enable` 保持开启，富文本字段单独处理；
9. **敏感数据**：密码只存哈希（`PasswordEncoder`），`passWordPlainText` 类字段仅历史兼容，新表禁止设计；日志、异常、接口响应中不得出现明文手机号、身份证、令牌；文件下载、导出接口需校验数据权限。

### 9.3 依赖与配置红线

10. **不要随便新增第三方依赖**：版本必须登记进 `xht-framework-dependencies` BOM，新增需评估许可证与已知漏洞；
11. **不要把敏感信息提交进仓库**：密码/密钥只放 Nacos 或环境变量；`application.yml` 中 `@...@` 占位符由 Maven profile 过滤替换，不要改成硬编码；
12. **不要提交与需求无关的格式化改动**，一次提交只做一件事。

### 9.4 高频踩坑

13. **`@IgnoreAuth` 类级/方法级语义不同**：类上只进白名单、不校验内部头；方法级才校验。类级 + 方法级直接并存会启动报错（接口继承场景只告警）；
14. **内部头 `auth-value` 三个服务必须同值**，缺失时内部接口一律 403（fail-closed）——服务间调用报 403 先查 `XHT_SECURITY_AUTH_VALUE`；
15. **Feign 降级不会自动生效**：需开启 `spring.cloud.openfeign.circuitbreaker.enabled=true` + 熔断实现，当前仓库未开启，降级类只是装配到位；且降级类必须实现 Feign 子接口，只实现父接口会返回 `null`；
16. **降级 ≠ 拿到空结果**：`ROptional` 在 `code != 200` 时抛异常，调用方必须显式处理，禁止 `resp.getData()` 直接用；
17. **`@BLog` 落库方式由 `xht.blog.repository-type` 决定**：`default` 只 debug 输出不落库；非 admin 服务配 `jdbc` 会因缺 Bean 静默失效；Feign 上报是同步调用，须配短超时，否则 admin 不可达时阻塞业务线程；`b_log` 表缺 `title`/`log_desc` 列时日志静默消失；
18. **审计字段（createBy/updateBy/delFlag）由框架自动填充**，手动 set 会覆盖自动填充；`createBy` 填的是 `username` 而非 userId；
19. **逻辑删除的坑**：自定义 XML 查询必须自己加 `del_flag = 0`（MP 只改写自带方法）；逻辑删除表的唯一索引要评估删除后重建冲突；
20. **异步线程取不到用户与 traceId**：`SecurityContext`/MDC 基于 ThreadLocal，提交任务前必须显式传参 / 传递 MDC；
21. **分页 long 字段序列化为字符串**：前端按字符串或数值双兼容处理，后端不要改序列化器；
22. **网关已关 `discovery.locator`**：按服务名直连的 `/xht-admin/**` 不可用，调试走 `/admin/**` 显式前缀或直连端口；`/api/**` 内部接口网关直接 404（`InternalApiGuardFilter` 按入站路径判定，含编码变体），只能 Feign 直连；`xht.gateway.internal-api.roots` 修改后需重启网关；
23. **文件上传**：`xht.file.upload.max-size` 需小于 `spring.servlet.multipart.max-file-size`；必须校验后缀 + 实际文件类型，不只信 `Content-Type`；文件名用存储 Key，防路径穿越。
