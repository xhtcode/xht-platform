# 开发规范和编码指南

> 适用范围：xht-platform 全部后端模块（`xht-framework-parent`、`xht-auth`、`xht-gateway`、`xht-admin`、`xht-generate`、`xht-platform-common`、`xht-platform-client`）。  
> 更新日期：2026-10-19

## 1. 总则

### 1.1 规范定位

本文档描述的是**本项目当前实际执行的约定**，而不是通用最佳实践清单。所有示例均取自仓库真实代码，命名、注解组合、包位置以现有实现为准。

### 1.2 术语

| 术语                      | 含义                                                                   | 所在层            |
| ----------------------- | -------------------------------------------------------------------- | -------------- |
| `Form`                  | 新增/修改的提交对象，继承 `BasicForm`                                            | domain         |
| `Query`                 | 查询条件对象，继承 `PageBasicQuery` 或 `BasicQuery`                            | domain         |
| `Response`              | 对外返回的视图对象，通常是 Entity 的子集                                             | domain         |
| `VO`                    | 聚合视图对象（跨表、跨服务拼装），继承 `BasicResponse`                                  | domain         |
| `BO`                    | 仅服务内部使用的业务对象，不外泄                                                     | infrastructure |
| `Entity`                | 与数据库表一一映射的持久化对象                                                      | infrastructure |
| `Converter`             | Entity 与 Form/Response/VO 之间的转换器（MapStruct）                          | infrastructure |
| `DAO`                   | 数据访问仓储接口，屏蔽 Mapper 细节                                                | infrastructure |
| `Common`                | 模块级公共包（`xht-admin-common` / `xht-generate-common`），放跨层复用的契约、枚举、常量、工具 | common         |
| `Api 契约`                | 服务间调用接口（`@FeignClient`），放在 common 的 `{域}/api` 包，服务端与调用方共用同一份         | common         |
| `Client`                | 服务间调用装配模块（`xht-platform-client-*`），负责注册 Feign、注入降级、向外暴露门面            | client         |
| `门面（Factory/Publisher）` | 业务真正注入的接口（`ISysDictFactory`、`IMessagePublisher`），隔离 Feign 与缓存细节      | common         |

### 1.3 规范效力与冲突裁决

1. 本文档与代码冲突时，**先修文档**，同时在「附录 C 代码待修正清单」登记需要改造的代码项，不允许文档长期与实现背离。
2. 评审以本文档为准；确需例外的，须在 PR 描述中说明原因并经模块负责人确认。
3. 严禁提交与本次需求无关的格式化改动，避免污染 diff。

## 2. 工程结构与分层

### 2.1 模块全景

```
xht-platform
├── xht-framework-parent              # 框架父工程：core + dependencies(BOM) + 10 个 starter
├── xht-auth                          # 认证中心（OAuth2 授权服务器），单体服务，不分层
├── xht-gateway                       # 网关（WebFlux），单体服务，不分层
├── xht-admin                         # 后台管理服务，四层（adapter/domain/infrastructure/start）
├── xht-generate                      # 代码生成服务，四层（adapter/domain/infrastructure/start）
├── xht-platform-common               # 模块级公共包，一服务一包，无业务实现
│   ├── xht-admin-common              #   admin 的公共包：Feign 契约、契约 VO、门面、文件工具、站内信模型
│   └── xht-generate-common           #   generate 的公共包：生成器常量、生成器枚举
└── xht-platform-client               # 服务间调用装配层，一域一模块，一个模块一个自动装配类
    ├── xht-platform-client-blog      #   操作日志上报（Feign → xht-admin）
    ├── xht-platform-client-dict      #   字典查询（Feign + Redis 缓存 → xht-admin）
    └── xht-platform-client-message   #   站内信发送（Feign → xht-admin）
```

> `xht-platform-common` 与 `xht-platform-client` 是**两个不同的层次**：前者只放「被共享的代码」，后者只放「让共享代码跑起来的自动装配」。业务模块永远只依赖前者 + 后者，绝不依赖对方服务的 `*-domain` / `*-infrastructure`。

### 2.2 四层职责

| 层              | 模块示例                       | 只允许放                                                                                        | 禁止                                                              |
| -------------- | -------------------------- | ------------------------------------------------------------------------------------------- | --------------------------------------------------------------- |
| adapter        | `xht-admin-adapter`        | `controller`、内部 Feign 服务端 `client/*`                                                        | 业务逻辑、直接访问 DAO                                                   |
| domain         | `xht-admin-domain`         | `domain/form`、`domain/query`、`domain/response`、`domain/vo`、`enums`、`service`（接口）、常量             | Web **行为性**类型（`@RestController`、`ResponseEntity`）、MyBatis、任何 infrastructure 类 |
| infrastructure | `xht-admin-infrastructure` | `service`（实现）、`dao` + `dao.impl` + `dao.mapper`、`entity`、`converter`、`properties`、`manager` | 被 adapter 之外的模块反向依赖                                             |
| start          | `xht-admin-start`          | 启动类、`config`、`application.yml`、`logback-spring.xml`                                         | 业务代码                                                            |

**关键约定**：Service **接口在 domain、实现在 infrastructure**，两侧包名保持一致，**不建 `service.impl` 子包**。

**Web 参数类型的边界**：Service 接口定义在 domain，因此 `MultipartFile`、`HttpServletRequest` 等**方法入参**属于接口签名的一部分，允许出现在 domain（现状：`IFileStorageService`、`ILoginService`）。禁止的是让 domain 承载 Web **行为**——不声明 `@RestController` / `@RequestMapping`、不返回 `ResponseEntity`、不依赖 `xht-web-spring-boot-starter`。这类入参由 Controller 原样透传，不在 Controller 侧拆解为 `InputStream` / `fileName` 再重组。

### 2.3 依赖方向

```
start ──► adapter ─────────► domain ──► common(xht-admin-common)
  │                             ▲            ▲
  └──────► infrastructure ──────┘            │
                                             │
调用方 start ──► xht-platform-client-{域} ───┘   # 只依赖 common + Feign，不依赖对方 domain
```

- `adapter → domain`、`infrastructure → domain`、`start → adapter + infrastructure`；
- `domain` 不依赖任何实现层，保证可被其它服务复用；
- `common` 位于依赖链最底层，只依赖 `xht-framework-*`，**禁止依赖任何业务模块**；
- `client` 只依赖 `common` 与 `xht-openfeign-spring-boot-starter`，只能由**调用方**在 `start`（或经 `domain → common` 传递）引入，**禁止被 `domain` / `infrastructure` 依赖**，否则会形成服务调用自身的环；
- 跨服务调用只能通过 `common` 中的 Feign 契约 + `client` 的自动装配，禁止直接依赖其它服务的 `*-domain`。

> 现状说明：`xht-admin-adapter` 通过 `xht-admin-domain` 传递拿到 `xht-admin-common`，所以 `adapter/client/*` 能直接 `implements` 契约接口；`xht-admin-infrastructure` 也显式声明了 `xht-admin-common`。

### 2.4 包结构

以 `xht-admin` 的「行政区划」为例：

```
# domain 层
com.xht.platform.area
├── AreaConstant.java                     # 域常量
├── domain
│   ├── form/SysAreaForm.java             # 继承 BasicForm
│   ├── query/SysAreaQuery.java           # 继承 PageBasicQuery
│   └── response/SysAreaResponse.java
├── enums/AreaHasChildEnum.java
└── service/ISysAreaService.java          # 接口

# infrastructure 层
com.xht.platform.area
├── converter/SysAreaConverter.java       # MapStruct
├── dao
│   ├── SysAreaDao.java                   # 仓储接口
│   ├── impl/SysAreaDaoImpl.java          # 继承 MapperRepositoryImpl
│   └── mapper/SysAreaMapper.java         # 继承 BaseMapperX
├── entity/SysAreaEntity.java             # 继承 BasicEntity
└── service/SysAreaServiceImpl.java       # 实现（与接口同包名，不同模块）

# adapter 层
com.xht.platform.controller.area.SysAreaController.java
com.xht.platform.client.dict.SysDictClientImpl.java   # 内部接口实现（实现在 adapter，契约在 common）
```

`adapter` 下的 `client/{域}` 只放「对外/对内 API 入口」，与 `controller` 平级；它依赖 `common` 的契约接口，不反向被 `common` 依赖。

`src/main/resources/mapper/{域}/*Mapper.xml` 放在 **infrastructure** 模块下，与 `dao.mapper` 包一一对应；`mapper-locations` 统一为 `classpath*:mapper/**/*Mapper.xml`。

### 2.5 starter 命名规范

自定义 starter 遵循 Spring Boot 官方建议的第三方 starter 命名格式：`{项目名}-spring-boot-starter`，禁止使用 `spring-boot-starter-{模块}` 形式（该前缀保留给官方 starter）。

- 正确：`xht-cache-spring-boot-starter`、`xht-web-spring-boot-starter`
- 错误：`xht-spring-boot-starter-cache`、`xht-spring-boot-starter-web`
- Spring Cloud 相关 starter 使用 `{项目名}-spring-cloud-starter`，如 `xht-spring-cloud-starter`
- 非 starter 的普通模块不加 `starter` 后缀，如 `xht-framework-core`、`xht-framework-dependencies`

### 2.6 包扫描特例

除 `xht-spring-cloud-starter` 的根包为 **`com.xht.cloud`** 外，其余框架模块均以 `com.xht.framework.*` 开头。业务启动类位于 `com.xht.platform`（admin/generate）或 `com.xht.auth`、`com.xht.gateway`，新增组件时注意包路径不要落到扫描范围之外。

### 2.7 模块级公共包 `xht-platform-common`

#### 2.7.1 定位

每个业务服务有一个自己的公共包，**只承载「被多层共享的代码」，不承载任何业务实现**（无 Controller、无 Service 实现、无 DAO、无 Entity）。

| 模块                    | 根包                        | 内容                                                                                                                                                                |
| --------------------- | ------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `xht-admin-common`    | `com.xht.platform.common` | 服务名常量、契约签名（`{域}/api`，**只有方法签名，不含 Feign / Web 注解**）、契约 DTO/VO（`{域}/domain`）、门面（`{域}/factory`，如 `dict/factory/ISysDictFactory`；无独立工厂的门面直接放 `{域}` 根，如 `message/IMessagePublisher`）、文件工具（`file/*`）、站内信模型（`message/*`）、前端路由模型（`router/dto`、`router/constant`）；Feign 客户端与降级实现**不在** common，见 9.2 |
| `xht-generate-common` | `com.xht.platform.common` | 服务名常量 `GenerateConstants`（`APPLICATION_NAME = "xht-generate"`）、生成器业务常量 `GenConstant`（`constant/`）、枚举 `DataBaseTypeEnum`/`GenStatusEnum`/`IdPrimaryKeyEnum`/`LanguageTypeEnum`/`PageStyleEnum`                         |

> 两个 common 共用 `com.xht.platform.common` 根包（历史上未按服务拆包），新增类前先确认类名不与另一个 common 冲突；确需新增子包时按 `{域}` 划分，不要再加 `admin` / `generate` 前缀。

> `xht-generate-common` 的两个常量类分工固定，不要互相搬家：`GenerateConstants` 只承载服务名（与 `AdminConstants` 同为常量接口风格），仅随服务名变化而改动；新增生成器业务常量一律进 `GenConstant`（`constant/`）。新增独立常量类建议用 `final class` + 私有构造，不再新建常量接口。

#### 2.7.2 包结构

```
com.xht.platform.common
├── AdminConstants.java              # 服务名等全局常量（APPLICATION_NAME = "xht-admin"）
├── {域}                             # dict / message / audit / file / router
│   ├── api/                         # 契约签名 IXxxClient（只有方法，无注解；调用方与服务端共用）
│   ├── domain/                      # 契约 DTO / VO，如 DictVO
│   ├── factory/                     # 对外门面 IXxxFactory（隔离 Feign + 缓存细节）
│   └── core/  bo/  constant/  enums/# 内部模型、BO、常量、枚举
└── ...
```

> 两个已存在的结构例外，不要求回头改造，但新增类不得仿照：
>
> - `router` 域：契约模型在 `router/dto`（`RouterDTO`、`RouterMetaDTO`），常量在 `router/constant`，未按 `domain/` 归位；
> - `message` 域：门面 `IMessagePublisher` 与其 `MessagePayloadBuilder` 直接位于 `message` 根包（该域没有独立工厂，不建 `factory/` 子包）。

#### 2.7.3 依赖约束（硬性）

1. 只允许依赖 `xht-framework-core`、`xht-log-spring-boot-starter`（与现有 `pom.xml` 一致）；**禁止**依赖 `xht-openfeign-spring-boot-starter` 与任何 Web 依赖——契约只写签名，`@FeignClient` / `@GetMapping` 等注解一律在 client 模块（见 9.2.1）；
2. **禁止**引入 `xht-web-spring-boot-starter`、`xht-mybatis-plus-spring-boot-starter`、任何 `*-domain` / `*-infrastructure`；
3. common 内的类不得带业务语义（如「新增用户」），只能是常量、模型、契约、纯工具；
4. common 一旦变更，所有依赖方都要回归，因此只允许**追加**，修改已有字段须评估兼容性。

#### 2.7.4 放 common 还是放 domain 的判定

| 场景                                           | 归属                                                          |
| -------------------------------------------- | ----------------------------------------------------------- |
| 两个及以上模块（含其它服务）共用的枚举、常量                       | `common`                                                    |
| 服务间调用的接口（`IXxxClient`）与其出入参 DTO              | `common` 的 `{域}/api` + `{域}/domain`                         |
| 只有本服务用的 `Form` / `Query` / `Response` / `VO` | `*-domain`                                                  |
| Entity / DAO / Converter / Service 实现        | `*-infrastructure`                                          |
| 只有本服务用的纯工具                                   | 优先 `common` 的 `{域}/utils`，避免在 adapter 与 infrastructure 各写一份 |

> 注意：`@Dict` 字典校验注解与其 `ConstraintValidator` **不在 common，而是随 `xht-platform-client-dict` 提供**（`com.xht.platform.dict.validation`）。原因：校验器强依赖该模块注册的 `ISysDictFactory`，放在 common 会变成"编译能过、运行期缺 bean"。因此**未引入 `xht-platform-client-dict` 的服务根本无法使用 `@Dict`**——配置错误前移到编译期。
>
> 使用要点：值为 `null`/空白时放行，字段必填请配合 `@NotBlank`；`disabled = true` 的字典项判定为不合法。

### 2.8 服务间调用装配层 `xht-platform-client`

#### 2.8.1 定位

一域一模块，每个模块**只做三件事**：声明 Feign 客户端子接口（`@FeignClient`）、注册降级工厂、把门面 bean 暴露给业务。不放任何业务逻辑。契约**签名**仍留在 `common`，client 只承载注解与装配。

| 模块                            | 依赖                                                   | 自动装配类                      | 暴露给业务的 bean                                                                                                             |
| ----------------------------- | ---------------------------------------------------- | -------------------------- | ----------------------------------------------------------------------------------------------------------------------- |
| `xht-platform-client-blog`    | `xht-admin-common` + `xht-log-spring-boot-starter`   | `BLogAutoConfiguration`    | `BLogRepository`（`BLogRepositoryImpl`，Feign 上报），仅 `xht.blog.repository-type=feign` 时生效；**已被 `xht-generate` 引入并启用**      |
| `xht-platform-client-dict`    | `xht-admin-common` + `xht-cache-spring-boot-starter` | `DictAutoConfiguration`    | `ISysDictFactory`（`SysDictApiFactory`，内置 Redis 缓存）＋ `@Dict` 字典校验注解与 `DictValidator`（`com.xht.platform.dict.validation`） |
| `xht-platform-client-message` | `xht-admin-common`                                   | `MessageAutoConfiguration` | `IMessagePublisher`（`MessageClientPublisher`）                                                                           |

> 引入现状：只有 `-blog` 被 `xht-generate` 实际引入（配套 `xht.blog.repository-type: feign`）；`-dict`、`-message` 已有模块与自动装配，但当前无服务引入，属预留能力。引入时按 2.8.3 操作，不要因为没有使用方而删除自动装配类或清单文件。

#### 2.8.2 装配三件套（模板）

```java
@Slf4j
@Configuration(proxyBeanMethods = false)
@EnableFeignClients(clients = SysDictFeignClient.class)      // 精确注册 Feign 子接口，禁止全包扫描
public class DictAutoConfiguration {

    @Bean
    public SysDictClientFallbackFactory sysDictClientFallbackFactory() {   // 降级工厂显式注册
        return new SysDictClientFallbackFactory();
    }

    @Bean
    public ISysDictFactory sysDictClient() {
        return new SysDictApiFactory();
    }
}
```

并在 `src/main/resources/META-INF/spring/org.springframework.boot.autoconfigure.AutoConfiguration.imports` 写入一行全限定类名：

```
com.xht.platform.dict.DictAutoConfiguration
```

#### 2.8.3 调用方使用方式

```xml
<dependency>
    <groupId>com.xht.platform</groupId>
    <artifactId>xht-platform-client-dict</artifactId>
</dependency>
```

```java
@RequiredArgsConstructor
@Service
public class SysNoticeServiceImpl implements ISysNoticeService {

    private final ISysDictFactory sysDictFactory;   // 只注入门面，不注入 @FeignClient 契约
}
```

调用方**不需要**写 `@EnableFeignClients`、不需要配置 `url`，服务名由契约里的 `AdminConstants.APPLICATION_NAME` 决定。

#### 2.8.4 硬性约束

1. `@EnableFeignClients(clients = ...)` 必须精确列出契约，禁止 `basePackages = "com.xht"` 这类全包扫描：它会把其它服务的契约一并注册成 Feign 代理，既可能指向本环境不存在的服务，也会与 `contextId` 撞名；
2. `FallbackFactory` 位于 client 模块的 `client/factory`，由自动装配类以 `@Bean` 注册（**不要** `@Component` + `@ComponentScan`）：自动装配模块不该依赖调用方的扫描路径，漏扫时 `fallbackFactory` 属性找不到 bean，启动即失败；
3. 业务只依赖门面接口（`ISysDictFactory`、`IMessagePublisher`）或确需 `R` 原始结构时才直接注入契约；禁止在 `domain` / `infrastructure` 中注入 `@FeignClient`；
4. **服务提供方要提供本地 `@Primary` 门面实现**，避免「自己 Feign 自己」：如 `xht-admin` 的 `MessageSysPublisher` 标了 `@Primary`，本地注入到的是直连 Service 的实现；
5. 一个服务对应一个 client 模块，禁止跨服务混装；新增域时新建模块，不往已有模块里塞。


## 3. 命名规范

### 3.1 包命名

- 全小写，多级用 `.` 分隔，禁止下划线与大写；
- 业务包格式：`com.xht.platform.{业务域}.{层级}`，如 `com.xht.platform.system.dao.mapper`；
- 业务域按**功能**划分（`system`、`dict`、`notice`、`area`、`file`、`oauth2`、`audit`），不按技术分层再套业务；
- 公共包格式：`com.xht.platform.common.{业务域}.{职责}`（`api` / `domain` / `factory` / `validation` / `core` / `bo` / `enums` / `constant` / `utils`），如 `com.xht.platform.common.dict.api`；
- 服务调用装配包格式：`com.xht.platform.{业务域}`，只放 `XxxAutoConfiguration` 与该域的实现适配类（如 `com.xht.platform.dict.factory`、`com.xht.platform.message.impl`）。

### 3.2 类命名

统一大驼峰（PascalCase），后缀固定：

| 类型              | 后缀                             | 示例                                                       |
| --------------- | ------------------------------ | -------------------------------------------------------- |
| 控制器             | `Controller`                   | `SysAreaController`                                      |
| 服务接口            | `I` + `Service`                | `ISysAreaService`                                        |
| 服务实现            | `ServiceImpl`                  | `SysAreaServiceImpl`                                     |
| 仓储接口            | `Dao`                          | `SysAreaDao`                                             |
| 仓储实现            | `DaoImpl`                      | `SysAreaDaoImpl`                                         |
| MyBatis Mapper  | `Mapper`                       | `SysAreaMapper`                                          |
| 实体              | `Entity`                       | `SysAreaEntity`                                          |
| 新增/修改表单         | `Form`                         | `SysAreaForm`                                            |
| 查询条件            | `Query`                        | `SysAreaQuery`                                           |
| 响应对象            | `Response`                     | `SysAreaResponse`                                        |
| 聚合视图            | `VO`（统一大写，禁止 `Vo`）             | `SysUserVO`                                              |
| 内部业务对象          | `BO`（统一大写，禁止 `Bo`）             | `GenCodeCoreBO`                                          |
| 转换器             | `Converter`                    | `SysAreaConverter`                                       |
| 服务间契约           | `I` + `Client`（只写签名）           | `ISysDictClient`                                         |
| 服务间 Feign 客户端   | `XxxFeignClient`（承载注解）         | `SysDictFeignClient`                                     |
| 门面              | `I` + `Factory` / `Publisher`  | `ISysDictFactory`、`IMessagePublisher`                    |
| 降级              | `Fallback` / `FallbackFactory` | `SysDictClientFallback`、`SysDictClientFallbackFactory`   |
| 自动装配（client 模块） | `AutoConfiguration`            | `DictAutoConfiguration`                                  |
| 配置类             | `Config` / `Properties`        | `ThreadPollConfig`、`LoginProperties`                     |
| 枚举              | `Enum` / `Enums`               | `AreaHasChildEnum`、`RoleTypeEnums`                       |
| 工具类             | `Utils` / `Helper`             | `StringUtils`、`SysUserHelper`                            |
| 自动装配            | `AutoConfiguration`            | `MybatisAutoConfiguration`                               |
| 异常              | `Exception`                    | `CaptchaException`                                       |

**禁止**：`XXFormRequest`、`XXQueryRequest`、`XXDTO` 这类历史命名；实现类带接口前缀（如 `ISysNoticeServiceImpl`）。

### 3.3 方法命名

小驼峰，动词 + 名词，同类操作跨模块保持一致：

| 语义  | 命名                         | 说明                                                |
| --- | -------------------------- | ------------------------------------------------- |
| 新增  | `create`                   | Controller/Service 统一用 `create`，不用 `add`/`insert` |
| 修改  | `updateById`               | 需要主键的更新                                           |
| 删除  | `remove` / `removeById`    | 逻辑删除语义也用 `remove`                                 |
| 单查  | `findById`                 | 返回 `XxxResponse`，查不到返回 `null` 由上层判空               |
| 分页  | `findPageList` / `findXxxPageList` | 默认分页统一 `findPageList`；按作用域区分时用 `findAdminPageList`、`findMyPageList`、`findAdminSendPageList`，禁止用 `page` / `selectXxxPage` |
| 列表  | `listByXxx` / `list`       | 不分页                                               |
| 树   | `findTree` / `getDeptTree` | 树形结构                                              |
| 存在性 | `exists` / `existsXxx`     | 返回 `boolean`                                      |
| 校验  | `checkXxx`                 | 私有校验方法                                            |

- 布尔返回值以 `is`/`has`/`exists` 开头，禁止 `getIsXxx`；
- 转换方法固定 `toEntity` / `toResponse`，分页转换由 `PageConverter#toResponse(Page)` 提供。

### 3.4 变量与常量

- 局部变量小驼峰，禁止单字母（循环变量 `i`/`j` 除外）；
- 常量全大写下划线分隔，集中放在域常量类（如 `AreaConstant`）或框架 `RConstants`；
- 魔法值一律提常量或枚举，禁止在业务代码里写 `"0"`、`"1"`、`"admin"` 这类字面量。

### 3.5 数据库命名

| 对象   | 规则                 | 示例                                             |
| ---- | ------------------ | ---------------------------------------------- |
| 表    | 小写下划线，按域加前缀        | `sys_user`、`sys_dict_item`、`gen_table`、`b_log` |
| 字段   | 小写下划线              | `create_time`、`del_flag`、`user_name`           |
| 主键   | `id`（bigint 自增或雪花） | `id`                                           |
| 索引   | `idx_{表}_{字段}`     | `idx_sys_user_user_name`                       |
| 唯一索引 | `uk_{表}_{字段}`      | `uk_sys_dict_dict_code`                        |

- 后台管理域统一 `sys_` 前缀，代码生成域 `gen_` 前缀，框架级日志表 `b_log`；
- 实体类名 = 表名去前缀后的驼峰（`sys_dict_item` ↔ `SysDictItemEntity`），字段名 = 列名驼峰；
- 布尔语义列用 `is_xxx`（tinyint），状态列用 `xxx_status` 并配枚举。

### 3.6 Redis Key

- 统一前缀 `xht:`，格式 `xht:{业务}:{标识}`，如 `xht:dict:{dictCode}`、`xht:rememberMe`；
- Key 前缀由配置驱动（`xht.global.dict.key-prefix`、`xht.security.remember-me.cache-key`），禁止硬编码；
- 必须设置过期时间，永久 Key 需在评审中说明理由。

### 3.7 配置项

- 业务配置统一挂 `xht.` 前缀，按域二级分组：`xht.security.*`、`xht.file.*`、`xht.oauth2.*`、`xht.blog.*`；
- 配置类用 `@ConfigurationProperties(prefix = "xht.xxx")` + `@Validated`，禁止散落的 `@Value`；
- 敏感值（密码、密钥）只允许出现在 Nacos 或环境变量，不进 Git。

### 4.2 Service

接口（domain 层）：

实现（infrastructure 层）：

```java
@Slf4j
@Service
@RequiredArgsConstructor
public class SysAreaServiceImpl implements ISysAreaService {

    private final SysAreaDao sysAreaDao;
    private final SysAreaConverter sysAreaConverter;

    @Override
    @Transactional(rollbackFor = Exception.class)
    public void create(SysAreaForm form) {
        checkForm(null, form);
        sysAreaDao.save(sysAreaConverter.toEntity(form));
    }

    private void checkForm(Long areaId, SysAreaForm form) {
        AssertUtils.notNull(form, "表单参数不能为空");
        boolean existsAreaCode = sysAreaDao.existsAreaCode(form.getAreaCode(), areaId);
        AssertUtils.isTrue(!existsAreaCode, "区划编码已存在");
    }
}
```

强制要求：

1. 写方法必须标注 `@Transactional(rollbackFor = Exception.class)`；
2. 业务校验用 `AssertUtils`（失败抛 `BusinessException`），禁止 `if (...) throw new RuntimeException(...)`；
3. Service 只依赖本域 DAO 与 Converter，跨域调用走对端 Service 接口，不直接注入其它域 DAO；
4. 返回 `Response`/`VO`，**禁止把 Entity 作为 Service 返回值**；
5. 事务内禁止调用远程服务（Feign）、发送消息、发起 HTTP 请求，必要时通过事件或事务提交后回调。

### 4.3 DAO

```java
public interface SysAreaDao extends MapperRepository<SysAreaEntity> {

    void updateHasChild(String areaCode, AreaHasChildEnum hasChild);

    boolean existsAreaCode(String areaCode, Long id);

@Slf4j
@Repository
public class SysAreaDaoImpl extends MapperRepositoryImpl<SysAreaMapper, SysAreaEntity> implements SysAreaDao {

    @Override
    public boolean existsAreaCode(String areaCode, Long id) {
        LambdaQueryWrapper<SysAreaEntity> wrapper = new LambdaQueryWrapper<>();
        wrapper.eq(SysAreaEntity::getAreaCode, areaCode);
        wrapper.ne(condition(id), SysAreaEntity::getId, id);
        return exists(wrapper);
    }

    @Override
    protected SFunction<SysAreaEntity, ?> getFieldId() {
        return SysAreaEntity::getId;
    }
}
```

```java
@Mapper
public interface SysAreaMapper extends BaseMapperX<SysAreaEntity> {
}
```

强制要求：

1. 仓储接口继承 `MapperRepository`，实现继承 `MapperRepositoryImpl<Mapper, Entity>` 并实现 `getFieldId()`；
2. Mapper 必须继承 `BaseMapperX`，**禁止**直接继承原生 `BaseMapper`；
3. 简单条件用 `LambdaQueryWrapper` / `LambdaUpdateWrapper`，字段引用一律用方法引用（`SysAreaEntity::getAreaCode`），禁止写字符串列名；
4. 条件拼接使用基类的 `condition(...)` 判断，避免 `if` 堆叠；
5. 复杂多表查询才写 XML，放在 `infrastructure/src/main/resources/mapper/{域}/`，文件名为 `{实体}Mapper.xml`；
6. DAO 方法不返回 `null` 语义的集合，统一返回空集合。

- 传播行为保持默认 `REQUIRED`，确需 `REQUIRES_NEW` 的在注释中说明原因。

## 5. 统一响应与异常

### 5.1 统一响应体 `R`

`com.xht.framework.common.domain.R<T>`：

| 字段         | 类型           | 说明                                    |
| ---------- | ------------ | ------------------------------------- |
| `code`     | Integer      | 业务码，**不是** HTTP 状态码；`200` 成功、`500` 失败 |
| `msg`      | String       | 提示信息（注意字段名是 `msg`，不是 `message`）       |
| `data`     | T            | 业务数据                                  |
| `dataType` | DataTypeEnum | 数据类型：`NORMAL` / `ENCRYPT`             |
| `traceId`  | String       | 链路追踪 ID，便于日志定位                        |

成功：

```json
{
  "code": 200,
  "msg": "成功！",
  "data": { "id": 1, "areaName": "北京市" },
  "dataType": "NORMAL",
  "traceId": "b7f1c0e2a9d34f56"
}
```

失败：

```json
{
  "code": 500,
  "msg": "区划编码已存在",
  "data": null,
  "dataType": "NORMAL",
  "traceId": "b7f1c0e2a9d34f56"
}
```

构造方式（禁止 `new R<>()`）：

```java
R.ok().build();                  // 无数据
R.ok().build(data);              // 带数据
R.error(errorCode).build();      // 指定错误码
R.ok().encrypt().build(data);    // 响应体加密
```

### 5.2 分页响应 `PageResponse`

```java
public class PageResponse<T> extends BasicResponse {
    private long current;   // 当前页
    private long size;      // 每页条数
    private long pages;     // 总页数
    private long total;     // 总条数
    private List<T> records;// 结果集
}
```

4 个 long 字段通过 `CustomLongSerializer` 序列化为字符串，避免前端精度丢失，前端按字符串或数值兼容处理。

### 5.3 错误码 `ErrorCode`

```java
public interface ErrorCode {
    int getCode();
    String getMessage();
}
```

- 每个业务域定义自己的错误码枚举（如 `SysUserErrorCode`），实现 `ErrorCode`；
- 错误码分段：`sys` 域 1xxxx、`gen` 域 2xxxx、认证 3xxxx，具体分段由模块负责人维护；
- **禁止**在业务代码中硬编码错误码数字或直接 `new BusinessException("xxx")` 传业务提示（提示文案应来自枚举，自定义文案仅用于补充上下文）。


### 5.4 异常与断言

| 场景        | 做法                                                  |
| --------- | --------------------------------------------------- |
| 参数/业务规则校验 | `AssertUtils.notNull / isTrue / hasText / notEmpty` |
| 明确的业务错误   | `throw new BusinessException(ErrorCode)`            |
| 需要自定义文案   | `throw new BusinessException(ErrorCode, "自定义提示")`   |
| 包装底层异常    | `throw new BusinessException(ErrorCode, e)`，保留堆栈    |
| 不可恢复的编程错误 | 直接抛运行时异常，交由全局处理器兜底                                  |

禁止事项：

- 禁止 `catch (Exception e) {}` 吞异常；
- 禁止 `e.printStackTrace()`；
- 禁止在 Controller 里 `try-catch` 后手工拼 `R.error()`（业务异常由全局处理器统一转换）。

### 5.5 全局异常处理

框架在 `xht-web-spring-boot-starter` 中注册了 `DefaultGlobalExceptionHandler`，统一处理 `BusinessException`、参数校验异常、`HttpMessageNotReadableException` 等，并输出 `R` 结构。业务服务不重复定义同类处理器；确需扩展时新增 `@RestControllerAdvice` 并设置更高 `@Order`，只处理自有异常类型。

## 6. 接口设计与权限

### 6.1 路径规范（现状约定）

本项目**不采用纯 RESTful 风格**，统一使用「资源前缀 + 动作」的动词式路径。这是当前全部 23 个 Controller、127 个端点的实际写法（`xht-admin` 16 个 / 93 个，`xht-generate` 7 个 / 34 个，统计口径为 `*/controller/**`；`adapter/client/*` 下的 3 个内部 Feign 服务端端点不计入），新增接口必须保持一致。

| 操作   | HTTP 方法 | 路径模式                              | 示例                                                   |
| ---- | ------- | --------------------------------- | ---------------------------------------------------- |
| 新增   | POST    | `{前缀}/create`                     | `POST /sys/area/create`                              |
| 修改   | POST    | `{前缀}/update/{id}`                | `POST /sys/area/update/{areaId}`                     |
| 删除   | POST    | `{前缀}/remove/{id}`                | `POST /sys/area/remove/{areaId}`                     |
| 详情   | GET     | `{前缀}/get/{id}`                   | `GET /sys/area/get/{areaId}`                         |
| 分页   | POST    | `{前缀}/page`                       | `POST /sys/user/page`，body `{"current":1,"size":10}` |
| 列表   | GET     | `{前缀}/list` 或 `{前缀}/list/{父级}`    | `GET /sys/area/list/{parentAreaCode}`                |
| 树    | GET     | `{前缀}/tree`                       | `GET /sys/menu/tree`                                 |
| 状态变更 | POST    | `{前缀}/updateStatus/{id}/{status}` | `POST /sys/role/updateStatus/{roleId}/{roleStatus}`  |
| 业务动作 | POST    | `{前缀}/{动作}/{id}`                  | `POST /sys/notice/publish/{noticeId}`                |

资源前缀规则：

- 后台管理：`/sys/{资源}`，二级资源嵌套（`/sys/dict/item`、`/sys/notice/type`、`/sys/user/role`）；
- 代码生成：`/gen/{资源}`，二级资源嵌套（`/gen/table/info`、`/gen/template/group`）；
- 内部服务接口：`/api/{原前缀}`（如 `/api/sys/dict`），只允许服务间调用；
- 登录相关：`/login/form`、`/login/phone`。

硬性约束：

1. **写操作一律 POST**，禁止使用 PUT / DELETE / PATCH；
2. 同一资源只保留一种动作写法，不允许同时存在 `/create` 与 `/add`；
3. 路径段小写，不出现下划线；确需驼峰动作（`underShelve`、`syncTable`）时全项目统一并评审确认；
4. 网关访问路径需加服务前缀：`/admin/sys/area/create`、`/generate/gen/code/view`（`StripPrefix=1`）。

### 6.2 请求参数与校验

```java
public class SysAreaForm extends BasicForm {

    @NotEmpty(message = "区划编码参数不合法", groups = {Groups.Create.class, Groups.Update.class})
    @Schema(description = "区划编码")
    private String areaCode;
}
```

- 提交对象继承 `BasicForm`，查询对象继承 `PageBasicQuery`（分页）或 `BasicQuery`（不分页）；
- 校验注解必须带 `groups`，由 Controller 的 `@Validated(Groups.Xxx.class)` 触发；
- 每个字段必须有 `@Schema(description = "...")`，否则文档不可读；
- 统一使用 `jakarta.validation`，禁止 `javax.validation`。

### 6.3 分页

```java
@Operation(summary = "分页查询系统用户")
@PostMapping("/page")
public R<PageResponse<SysUserResponse>> findPageList(@RequestBody SysUserQuery query) {
    return R.ok().build(sysUserService.findPageList(query));
}
```

- 入参统一用 `@RequestBody` 接收 JSON 查询对象（`Content-Type: application/json`），不再用 query string 传分页与筛选条件；GET 仅用于详情、列表、树等不分页查询；
- body 为空会返回 400，无筛选条件时也要传 `{}`；
- `LocalDateTime` 字段按全局反序列化器传 `yyyy-MM-dd HH:mm:ss`，不要传 ISO 的 `T` 格式；
- 枚举筛选字段优先传枚举值（`@JsonValue` 对应的数值或字符串），以各枚举的 `@JsonValue` 为准；
- 分页字段固定 `current` / `size`（来自 `PageBasicQuery`），**不是** `pageNum` / `pageSize`；
- 返回 `R<PageResponse<T>>`；分页作用域用路径区分（`/admin/page`、`/my/page`），不加额外参数；
- Service 内部通过 `PageTool.getPage(query)` 构造 `Page`，DAO 返回 `Page<Entity>`，Converter 转 `PageResponse<Response>`。

### 6.4 权限注解

| 注解                              | 来源                    | 语义                                  | 使用位置   |
| ------------------------------- | --------------------- | ----------------------------------- | ------ |
| `@CheckMenu("sys:area:remove")` | `xht-resource-server` | 校验菜单/按钮权限码，支持逗号分隔多值                 | 方法     |
| `@CheckRole("admin")`           | `xht-resource-server` | 校验角色编码                              | 方法     |
| `@IsAdmin`                      | `xht-resource-server` | 仅管理员可访问                             | 方法     |
| `@IgnoreAuth`                   | `xht-security`        | 免鉴权：加入 URL 白名单；方法级（含契约接口方法）按 `aop` 决定是否校验内部调用头 | 类 / 方法 |

权限码命名：`{模块}:{资源}:{动作}`，如 `sys:user:create`、`sys:role:menu:bind`，与前端菜单按钮配置保持一致。

注意事项：

1. `@CheckMenu` / `@CheckRole` / `@IsAdmin` 依赖 `@EnableResourceServer` 开启的方法级安全，仅在引入 security starter 而未启用资源服务器时不生效；
2. `@IgnoreAuth` 标在**类**上只进白名单，不触发内部头校验；需要内部调用校验的接口必须标在**方法**上；
3. 方法级注解**支持从契约接口继承**：`XxxClientImpl` 漏标时，框架仍按接口方法上的注解校验内部头（`IgnoreAuthInterceptor` 与白名单共用同一套注解查找规则）；实现类显式重复标注便于阅读，也是推荐写法；
4. 对外开放接口用 `@IgnoreAuth(aop = false)` 显式关闭内部头校验（如 `GET /sys/area/list/{parentAreaCode}`）；
5. 同一 Controller 中**直接同时**声明类级与方法级 `@IgnoreAuth` 会启动期抛异常；若方法注解继承自接口、类上又声明了注解，只打告警不阻断启动。

### 6.5 当前登录用户上下文

统一通过 `com.xht.framework.oauth2.utils.SecurityUtils`（`xht-resource-server-spring-boot-starter`）获取，**禁止在业务代码里直接读 `SecurityContextHolder`**。

| 方法                    | 返回                         | 语义                                                                                   |
| --------------------- | -------------------------- | ------------------------------------------------------------------------------------ |
| `getAuthentication()` | `Optional<Authentication>` | 匿名请求（`AnonymousAuthenticationToken`）返回 `Optional.empty()`，用于「可能未登录」的场景               |
| `isLogin()`           | `boolean`                  | 是否已登录；匿名请求为 `false`                                                                  |
| `getUser()`           | `BasicUserDetails`         | 未登录、或 principal 不是 `BasicUserDetails` 时抛 `BasicAuthenticationException("用户认证信息不存在")` |
| `getUserId()`         | `Long`                     | 等价 `getUser().getUserId()`                                                           |
| `getUserName()`       | `String`                   | 登录账号（`username`，不是昵称）                                                                |
| `isAdmin()`           | `Boolean`                  | `userType == UserTypeEnum.ADMIN`                                                     |

`BasicUserDetails` 可取的字段（无需再查库）：

| 字段                                 | 类型                       | 典型用途                                                      |
| ---------------------------------- | ------------------------ | --------------------------------------------------------- |
| `userId` / `username` / `nickName` | Long / String / String   | 操作人标识、审计、日志                                               |
| `userType`                         | `UserTypeEnum`           | 区分管理员与普通用户（`isAdmin()` 依据）                                |
| `userStatus`                       | `UserStatusEnum`         | `NORMAL`/`LOCKED`/`DISABLED`/`EXPIRED`，决定 `isEnabled()` 等 |
| `deptId` / `deptName`              | Long / String            | 数据权限（部门范围）过滤                                              |
| `roleCodes`                        | `Set<String>`            | 角色编码，配合 `@CheckRole`                                      |
| `menuButtonCodes`                  | `Set<String>`            | 按钮权限码，与 `@CheckMenu` 同源，可用于接口内二次判断                        |
| `userPhone` / `loginType`          | String / `LoginTypeEnum` | 登录方式、脱敏展示                                                 |

业务归属校验示例：

```java
Long currentUserId = SecurityUtils.getUserId();
AssertUtils.isTrue(Objects.equals(currentUserId, record.getUserId()), "无权操作他人数据");
```

硬性约束：

1. 只有在**必然已登录**的接口里才能直接调用 `getUserId()` / `getUserName()` / `getUser()` / `isAdmin()`；标了 `@IgnoreAuth` 的接口、定时任务、MQ 消费者、异步线程必须先 `isLogin()` 或 `getAuthentication()` 判断；
2. 禁止业务代码写 `SecurityContextHolder.getContext().getAuthentication()`；框架内部的 `SecurityUtils`、`MybatisPlusSecurityMetaObjectHandler` 是唯一例外；
3. `createBy` / `updateBy` 审计字段由 `MybatisPlusSecurityMetaObjectHandler` 自动填 `username`，业务代码**不要**再手动 set；
4. `SecurityContext` 基于 `ThreadLocal`，`@Async` / 线程池 / 手动 `new Thread` 中取不到用户，必须在提交任务前把 `userId`、`userName` 作为参数传进去；
5. 需要「可能为空」的用户信息时，用 `getAuthentication().map(...)` 这类 Optional 链，不要 `try-catch` 吞 `BasicAuthenticationException`。

### 6.6 内部服务接口

```java
// common 中的契约签名（调用方与服务端共用，不带 Feign / Web 注解）
public interface ISysDictClient {
    R<List<DictVO>> getByDictCode(String dictCode);
}

// client-dict 中的 Feign 客户端（注解与路径只在调用方这一侧）
@FeignClient(name = AdminConstants.APPLICATION_NAME, contextId = "iSysDictClient",
             path = "/api/sys/dict", fallbackFactory = SysDictClientFallbackFactory.class)
public interface SysDictFeignClient extends ISysDictClient {
    @Override
    @FeignIgnoreAuth                          // 内部接口：调用时自动补内部调用头
    @GetMapping("/code/{dictCode}")
    R<List<DictVO>> getByDictCode(@PathVariable("dictCode") String dictCode);
}

// adapter 中的服务端实现
@RestController
@RequestMapping("/api/sys/dict")
@RequiredArgsConstructor
public class SysDictClientImpl implements ISysDictClient {

    private final ISysDictItemService sysDictItemService;

    @Override
    @IgnoreAuth                              // 内部接口，校验内部调用头；实现类建议显式标注
    @GetMapping("/code/{dictCode}")
    public R<List<DictVO>> getByDictCode(@PathVariable String dictCode) {
        return R.ok().build(sysDictItemService.getByDictCode(dictCode));
    }
}
```

- 契约接口（`IXxxClient`）与 DTO 放 `common` 的 `{域}/api`、`{域}/domain`；调用方引入 `xht-platform-client-*`，**服务端不引 client 模块**，而是让 `adapter` 直接 `implements` 契约，一份接口同时承担「Feign 描述」和「Spring MVC 映射」；
- 服务端实现放 `adapter` 的 `client/{域}/XxxClientImpl`，类上 `@RequestMapping("/api/...")` 与契约的 `path` 保持一致，方法上标注 `@GetMapping/@PostMapping` 与 `@IgnoreAuth`；
- `@IgnoreAuth` 的 `aop` 与服务端校验方式必须配对，见下表；
- 内部接口不对外暴露：网关已关闭 `discovery.locator`，并基于**入站原始路径**拒绝内部根路径（`InternalApiGuardFilter`，返回 404 而非 403，避免暴露接口存在）；内部接口只能由服务间 Feign 直连调用。受保护的根路径由 `xht.gateway.internal-api.roots` 配置，默认 `["/api"]`，可配多个，**修改后需重启网关**；

| 服务端 `@IgnoreAuth` | 调用方 `@FeignIgnoreAuth` | 效果                                                                                                        | 现有例子                                                    |
| ----------------- | ---------------------- | --------------------------------------------------------------------------------------------------------- | ------------------------------------------------------- |
| `aop = false`     | 不需要                    | 白名单放行，且**不校验**内部调用头                                                                                       | `QrLoginController`（对外公开接口）                            |
| `aop = true`（默认）  | 必须标注                   | 白名单放行，但**校验** `xht.security.header.auth-key/auth-value`；`auth-value` 未配置时一律拒绝（fail-closed，不会因双方都为 `null` 而放行） | `SysDictClientImpl` ↔ `ISysDictClient`、`SysMessageClientImpl` ↔ `ISysMessageClient`、`BLogClientImpl` ↔ `IBLogClient` |

> 校验由 `IgnoreAuthInterceptor`（`xht-security`）完成，与白名单共用 `AnnotationUtils` 的注解查找规则；接口方法上的注解会被识别，实现类是否重复标注不影响安全语义。

> 契约编写、降级工厂、自动装配的完整规范见 **9.2 服务间调用（Feign + Client）**。

## 7. 数据访问与 SQL

1. **MyBatis-Plus 优先**：单表 CRUD 全部走 `CrudRepository` / `BaseMapperX` 提供的方法，不写 XML；
2. **禁止 `SELECT *`**：XML 中显式列出字段，避免表结构变更导致映射错乱；
3. 参数一律 `#{}`，禁止 `${}` 拼接（排序字段等必须走白名单校验，参考 `AscName`/`DescName` 的处理）；
4. 分页统一走 MP 分页插件，禁止手写 `LIMIT`；
5. 批量操作使用基类的 `saveAll`（默认批 100）与 `IN` 查询分批（1000），避免超长 SQL；
6. **逻辑删除**：`DELETE` 语句由 MP 自动改写为 `UPDATE ... SET del_flag=1`；自定义 XML 中的查询必须自行追加 `del_flag = 0`；
7. 逻辑删除表的唯一索引需评估冲突风险（删除后重建同名数据会命中唯一键），建议唯一索引包含 `del_flag` 或改用业务唯一校验；
8. 多表关联查询超过 3 张表时，优先拆成多次单表查询在 Service 内组装，避免深度嵌套；
9. 新增/变更表结构必须同步更新 `doc/sql` 下的初始化脚本，并在 PR 中说明。

## 8. 日志与审计

### 8.1 日志

```java
@Slf4j
@Service
public class SysUserServiceImpl implements ISysUserService {

    public SysUserResponse findById(Long userId) {
        log.info("查询用户信息, userId: {}", userId);
        // ...
    }
}
```

- 统一 `@Slf4j`，禁止 `System.out.println`、禁止自建 `LoggerFactory`；
- 使用占位符 `{}`，禁止字符串拼接；
- 级别约定：`ERROR` 仅用于需要人工介入的失败；`WARN` 用于可恢复异常与降级；`INFO` 记录关键业务流转；`DEBUG` 记录调试细节，生产默认关闭；
- 异常日志必须带堆栈：`log.error("保存用户失败, userId: {}", userId, e)`；
- 禁止在日志中输出密码、令牌、身份证、手机号全量等敏感信息（见第 10 章）。

### 8.2 操作日志 `@BLog`

```java
@BLog(value = "用户管理", description = "重置用户密码")
@PostMapping("/reset/{userId}/pwd")
public R<Void> resetPassword(@PathVariable Long userId) { ... }
```

- `value` 与 `description` 均必填，`value` 用模块名，`description` 用「动作 + 对象」；
- 切面自动采集：操作人、IP、请求方式、请求参数（自动过滤 `HttpServletRequest`、`MultipartFile`、`HttpServletResponse`）、耗时、`traceId`、异常信息；
- 落库方式由 `xht.blog.repository-type` 决定：`default` 仅 `log.debug` 输出（**既不落库也不写文件**）、`feign` 上报到 `xht-admin`、`jdbc` 直接写库（**目前仅 `xht-admin` 提供该实现**，其它服务配 `jdbc` 会因缺少 `BLogRepository` Bean 导致切面不装配、`@BLog` 静默失效）；生产环境必须显式配置；
- `b_log` 表必须包含 `title`、`log_desc` 两列（`BLogEntity` 已映射）。缺列时插入报 `Unknown column 'title'`，异常被切面 `catch` 吞掉，表现为「一条日志都没有」，排查成本极高；
- 日志走 Feign 上报时是**同步**调用（切面在 `finally` 内执行），必须为该 client 配置短超时（如 `connect-timeout: 1000` / `read-timeout: 2000`），否则 admin 不可达时会阻塞业务线程到默认超时；
- 保存失败只记录 error，不影响主流程，因此不要依赖该日志做审计对账。

### 8.3 链路追踪

- `traceId` 由网关/过滤器生成，写入 MDC，`R.traceId` 自动回填；
- 跨服务调用由 `xht-openfeign-spring-boot-starter` 的拦截器透传；
- 异步线程需手动传递 MDC 上下文（参考 `ThreadPollConfig` 的线程池装饰），否则日志丢失 `traceId`。


### 8.4 脱敏

数据脱敏与日志脱敏为独立需求（见 `doc/开发需求.md`），实施后需遵守：

- 手机号、身份证、银行卡在 Response 中脱敏，日志中禁止出现原文；
- 密码只存哈希（`PasswordEncoder`），`passWordPlainText` 类字段仅用于历史兼容，新表禁止设计；
- 文件下载、导出接口需校验数据权限，防止越权拉取全量数据。

## 9. 缓存 / 服务间调用 / 消息 / 文件

### 9.1 缓存

```java
@RequiredArgsConstructor
@Service
public class SysDictServiceImpl implements ISysDictService {

    private final RedisRepository redisRepository;
}
```

- 统一使用 `RedisRepository`（`xht-cache-spring-boot-starter`），禁止直接注入 `RedisTemplate` 做业务缓存；
- Key 规范见 3.6，读写必须显式指定过期时间；
- 缓存更新策略：先更新库、再删缓存；禁止「先删缓存再写库」；
- 缓存穿透防护：空结果缓存短 TTL；缓存击穿：热点 Key 加互斥锁或逻辑过期；
- 字典等低频变更数据可全量缓存，用户/权限类数据必须按维度 Key 缓存并支持主动失效。

### 9.2 服务间调用（Feign + Client）

分工固定为四段，任何跨服务调用都必须按这四段落位：

| 关注点                                | 位置                                                |
| ---------------------------------- | ------------------------------------------------- |
| 契约签名（`IXxxClient`，不带注解）与出入参 DTO   | `common` 的 `{域}/api` + `{域}/domain`               |
| Feign 客户端（`@FeignClient` 子接口）      | `xht-platform-client-{域}` 的 `client/XxxFeignClient` |
| 降级（`Fallback` / `FallbackFactory`） | `xht-platform-client-{域}` 的 `client/fallback` + `client/factory` |
| 服务端实现                              | 被调方 `adapter` 的 `client/{域}/XxxClientImpl`        |
| 装配（注册 Feign + 暴露门面）                | `xht-platform-client-{域}`                         |

#### 9.2.1 契约编写

```java
// common：只写签名，不 import 任何 org.springframework.*
public interface ISysDictClient {
    R<List<DictVO>> getByDictCode(String dictCode);
}
```

```java
// client：承载全部注解；方法必须重声明，不依赖父接口注解继承
@FeignClient(
        name = AdminConstants.APPLICATION_NAME,          // 服务名必须用常量
        contextId = "iSysDictClient",                    // 必填且全局唯一，否则 Bean 名冲突
        path = "/api/sys/dict",                          // 与服务端 @RequestMapping 完全一致
        fallbackFactory = SysDictClientFallbackFactory.class
)
public interface SysDictFeignClient extends ISysDictClient {

    @Override
    @FeignIgnoreAuth                                   // 内部接口必须标注，否则对端会 403
    @GetMapping("/code/{dictCode}")
    R<List<DictVO>> getByDictCode(@PathVariable("dictCode") String dictCode);
}
```

1. 签名接口放 `com.xht.platform.common.{域}.api`，命名 `IXxxClient`，**禁止出现 Feign / Web 注解**（common 不依赖 openfeign）；服务端 `adapter` 只实现该签名接口；
2. Feign 子接口放 `com.xht.platform.{域}.client`，命名 `XxxFeignClient extends IXxxClient`；路径、`@FeignIgnoreAuth` 全部写在这一层，方法签名必须与父接口完全一致并**重声明注解**；
3. `name` 只能是 `AdminConstants.APPLICATION_NAME` 这类常量，禁止手写 `"xht-admin"`；
4. `contextId` 必填：同一服务多个契约时，默认 Bean 名会撞车；
5. `path` 用 `/api/...` 前缀，与 6.6 的路径规则一致；该前缀在网关侧按**入站路径**统一拒绝（含 `%2e%2e`、`%252e%252e`、`//`、`;` 等编码或归一化变体），只能服务间直连；
6. 返回值统一 `R<T>`，与 Controller 一致；出参 DTO 必须以 `VO` / `DTO` 结尾并放在 `{域}/domain`，禁止引用对方 `*-domain` 里的 `Response`。

#### 9.2.2 降级

```java
public class SysDictClientFallback extends BasicFallback implements SysDictFeignClient {

    public SysDictClientFallback(Throwable cause) { super(cause); }

    @Override
    public R<List<DictVO>> getByDictCode(String dictCode) {
        return error();          // 继承自 BasicFallback，等价 R.error().msg(cause.getMessage())
    }
}

@Slf4j
public class SysDictClientFallbackFactory implements FallbackFactory<SysDictFeignClient> {
    @Override
    public SysDictFeignClient create(Throwable cause) {
        return new SysDictClientFallback(cause);
    }
}
```

1. 降级类继承 `BasicFallback`，用 `error()` / `error(msg)` 返回 `R.error()`，**不要直接 `return null`**；
2. `FallbackFactory` 放在 client 模块的 `client/factory`，由自动装配类以 `@Bean` 注册（不用 `@Component` + `@ComponentScan`）；
3. 降级类必须实现 **Feign 子接口**（不是 `common` 的签名接口），泛型写 `FallbackFactory<XxxFeignClient>`。若只实现父接口，降级触发时 `Method.invoke` 会因不是该接口实例而失败、异常被框架吞掉后返回 `null`；
4. 降级只负责「给出可判定的失败结果」，是否兜底默认值由调用方决定。

> **降级的前提**：`fallback` / `fallbackFactory` 只在开启熔断后才参与调用，需要同时配置 `spring.cloud.openfeign.circuitbreaker.enabled=true` 并引入熔断实现（如 `spring-cloud-starter-circuitbreaker-resilience4j`）。两者缺一，工厂只是装配到位、**不会生效**，Feign 异常会直接抛给调用方。当前仓库尚未开启，评估降级效果时不要以「配了 fallback」为准。

#### 9.2.3 调用方处理返回值

```java
R<List<DictVO>> resp = sysDictClient.getByDictCode(dictCode);
List<DictVO> list = ROptional.of(resp).get().orElse(Collections.emptyList());
```

- `ROptional.of(r).get()` 成功返回 `Optional<T>`，`code != 200` 时抛 `BusinessException("data is error!")`；
- 因此**降级并不等于「自动拿到空集合」**：依赖降级的调用方要么用 `ROptional` 并接受异常，要么显式 `if (!Objects.equals(resp.getCode(), RConstants.SUCCESS))` 处理；
- 禁止 `resp.getData().forEach(...)` 这类不判空的写法。

#### 9.2.4 内部认证头

- 服务端 `@IgnoreAuth`（默认 `aop = true`）+ 契约方法 `@FeignIgnoreAuth` → `FeignIgnoreAuthInterceptor` 自动补 `SecurityHeaderProperties` 里的 `auth-key` / `auth-value`；
- 服务端 `@IgnoreAuth(aop = false)` → 契约**不加** `@FeignIgnoreAuth`，见 6.6 的配对表；
- `auth-value` 由环境变量 `XHT_SECURITY_AUTH_VALUE` 注入（仓库不存明文），三个服务必须取同一值；未配置时 `aop = true` 的接口一律拒绝访问（fail-closed）；Feign 侧 `auth-value` 为空不会发送该请求头，因此表现为对端 403 而非静默通过；
- `/api/**` 在网关侧按**入站路径**统一拒绝（`InternalApiGuardFilter`，含 `%2e%2e` / `%252e%252e` 等编码变体），因此三个内部契约（`ISysDictClient`、`ISysMessageClient`、`IBLogClient`）必须成对配置：契约标 `@FeignIgnoreAuth`、服务端标 `@IgnoreAuth`；
- `FeignTokenInterceptor` 负责透传当前用户令牌，`FeignTraceLogInterceptor` 负责 `traceId` 与请求日志，三者由 `xht-openfeign-spring-boot-starter` 自动装配，业务无需配置。

#### 9.2.5 门面（可选但推荐）

Feign 契约描述「怎么调」，门面描述「业务怎么用」。带缓存、带默认值、需要多接口聚合时，在 `common` 的 `{域}/factory` 定义 `IXxxFactory`，由 client 模块提供实现：

```java
public class SysDictApiFactory implements ISysDictFactory {   // client-dict 中
    @Override
    public List<DictVO> getDictList(String dictCode) {
        return redisRepository.getSet(cacheKey, timeout, unit,
                () -> ROptional.of(sysDictClient.getByDictCode(dictCode)).get().orElse(Collections.emptyList()));
    }
}
```

- 业务只注入 `ISysDictFactory` / `IMessagePublisher`，不感知 Feign；
- 服务提供方（`xht-admin`）自己用同一门面时，提供 `@Primary` 的本地实现（`MessageSysPublisher`），避免自调用绕一圈网络。

#### 9.2.6 新增一个服务间调用的 7 步

1. 在 `common` 的 `{域}/api` 定义 `IXxxClient` —— **只写方法签名**，不带任何 Feign / Web 注解，服务端与调用方共用；
2. 在 `{域}/domain` 新增出入参 `XxxDTO` / `XxxVO`；
3. 新建 `xht-platform-client-{域}` 模块：pom 依赖 `xht-admin-common` + `xht-openfeign-spring-boot-starter`（+ 需要的 `xht-cache-spring-boot-starter`）；
4. 在该模块 `client/` 下写 `XxxFeignClient extends IXxxClient`，承载 `@FeignClient`、`@GetMapping`、`@FeignIgnoreAuth`，方法注解必须重声明；在 `client/fallback`、`client/factory` 补降级类（工厂**不用** `@Component`）；
5. 写自动装配类：`@EnableFeignClients(clients = XxxFeignClient.class)`、`@Bean` 注册降级工厂与门面实现，并写入 `AutoConfiguration.imports`；
6. 被调方 `adapter` 的 `client/{域}` 新增 `XxxClientImpl implements IXxxClient`（实现的是 common 的签名接口），`@RequestMapping` 与 `path` 一致，标注 `@IgnoreAuth`（按 6.6 配对表决定 `aop`；接口已标注时实现类不再标注也不会漏校验，但建议显式写出）；
7. 在根 `pom.xml` 的 `<dependencyManagement>` 与 `<modules>` 中登记新模块；调用方 `start` 引入 `xht-platform-client-{域}`，注入门面或契约，按 9.2.3 处理返回值。

> 若调用方只需要「日志落库」「站内信」这类既有能力，直接引 `xht-platform-client-blog` / `-message` 即可，不要重复造契约。

通用约束：

- Feign 调用**不放在事务内**，也不要在 `@Transactional` 方法尾部顺手调用；必要时改用事务提交后事件；
- 超时、重试按接口特性在 Nacos 中单独配置，禁止全局一刀切；
- 一个契约对应一个 `contextId`，一个服务对应一个 client 模块，禁止「一个大客户端」包打所有服务。

### 9.3 消息

- 站内信统一通过 `IMessagePublisher#publish(topic, payload)` 发布：
  - 调用方引 `xht-platform-client-message`，注入到的是 `MessageClientPublisher`（Feign → `xht-admin` 的 `/api/sys/message/send`）；
  - `xht-admin` 自身注入到 `@Primary` 的 `MessageSysPublisher`，直连 `ISysMessageService`，不走网络；
- 消息体必须用 `MessagePayloadBuilder` 构造，禁止手拼 `Map` 或 `new MessagePayload(...)`：

```java
MessagePayload payload = MessagePayloadBuilder.builder()
        .sender(sender)                                     // MessageUser
        .recipient(recipient)                               // 可多次调用，支持 List 批量
        .messageType(MessageTypeEnum.SYSTEM_NOTICE)         // 1-系统通知 / 2-业务提醒
        .messageTitle("导出任务已完成")
        .messageContent("文件「{fileName}」已生成")          // 支持占位符
        .build(extendInfo);                                 // MessageExtendInfo 提供占位符数据与跳转地址
```

- `sender`、`recipient`、`messageType`、`messageTitle`、`messageContent` 缺一即抛 `UtilException`，构造后不要再补 set；
- 消息发送失败必须记录日志并保留业务数据，不做「发消息失败就回滚业务」的强耦合设计（除非业务明确要求）；
- 新增消息类型先扩展 `MessageTypeEnum`，并在 `xht-admin` 侧确认站内信列表的展示与筛选逻辑。

## 10. 安全规范

1. **密钥外置**：内部头 `auth-value` 已改为环境变量注入（`xht.security.header.auth-value: ${XHT_SECURITY_AUTH_VALUE:}`），仓库内不再保留明文值；`xht-admin`、`xht-auth`、`xht-generate` 必须注入**同一个**值，缺失时 `aop = true` 的内部接口一律拒绝（fail-closed），表现为服务间调用 403。数据库密码、Redis 密码、`client-secret` 目前仍为明文示例值，新环境必须替换为 Nacos 加密配置或环境变量，禁止带入生产；
2. **越权防护**：所有按 ID 操作的接口必须校验数据归属（当前用户/当前租户/部门范围），不能只校验「已登录」；
3. **`@IgnoreAuth` 管控**：新增免鉴权接口需在 PR 中单独说明，禁止为「联调方便」放开；开放接口使用 `aop = false`，内部接口保持 `aop = true`；内部头 `auth-value` 缺失时 `aop = true` 的接口一律拒绝（fail-closed），不要依赖「双方都为 null 视为相等」的旧行为；
4. **注入防护**：SQL 一律参数绑定；XML 中动态排序字段必须白名单校验；
5. **XSS**：`xht.security.xss.enable` 保持开启；富文本字段单独处理，不做全局转义；
6. **文件安全**：限制后缀与大小，禁止上传可执行脚本；下载接口设置 `Content-Disposition` 与正确的 `Content-Type`；
7. **敏感数据**：密码不可逆存储；日志、异常信息、接口响应中不得出现明文手机号、身份证、令牌；
8. **依赖安全**：新增三方依赖需评估许可证与已知漏洞，版本统一在 `xht-framework-dependencies` 管理。

### 11.2 分支模型

- `main`：稳定发布分支，只接受 `release/*` 合并；
- `develop`：集成分支；
- `feature/xxx`：功能分支，从 `develop` 拉出；
- `bugfix/xxx`：缺陷修复分支；
- `release/xxx`：发布准备分支。

### 11.3 提交规范

格式：`类型: 描述`（中文描述，动词开头，不超过 50 字）

| 类型         | 用途        |
| ---------- | --------- |
| `feat`     | 新增功能      |
| `fix`      | 修复缺陷      |
| `refactor` | 重构（不改行为）  |
| `docs`     | 文档        |
| `style`    | 格式（不影响逻辑） |
| `test`     | 测试        |
| `chore`    | 构建、依赖、配置  |

- 一次提交只做一件事，避免「顺手格式化」；
- 提交前确保 `mvn -q -DskipTests compile` 通过。

### 11.4 版本发布

1. 从 `develop` 创建 `release/x.y.z`；
2. 在 release 分支完成测试与修复，版本号遵循语义化版本；
3. 合并到 `main` 并打 tag（`vX.Y.Z`）；
4. 回合到 `develop`；
5. 发布到目标环境并同步更新本文档「更新日期」。
