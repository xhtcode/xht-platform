# 模式 A：规范检查六项清单

对照项目规范文档检查代码时，按以下六项逐条核对。规范文档以实际内容为准，本清单只是检查的组织方式，不添加规范之外的规则。

## 检查项 1：命名

- 类名/文件名后缀（Controller、ServiceImpl、Dao、Mapper、Entity、Form、Query、Response、VO、BO、Converter、Client、Fallback、AutoConfiguration、Enum、Utils、Exception 等）是否符合规范第「命名规范」章的后缀表；
- 包名格式与业务域划分是否一致；
- 方法名（create / updateById / remove / findById / findPageList / listByXxx / toEntity / toResponse 等）是否与规范方法表一致；
- 变量、常量、数据库对象、Redis Key、配置项前缀是否合规。
- 注意：规范中【不一致点】标注的成对写法（如 `Enum`/`Enums`、`remove`/`removeById`）不判违规，仅当同一文件内混用两种时提示统一。

## 检查项 2：文件放置与导入路径

- 新代码是否落在规范「目录结构与模块职责」规定的层与包中；
- 跨层引用是否违反依赖方向（如 domain 依赖 infrastructure、依赖其它服务的 `*-domain`）；
- 公共代码归属判定（跨模块共用 → common；仅本服务 → domain 层）是否正确；
- Mapper XML 资源路径、配置文件位置是否合规。

## 检查项 3：组件/接口写法与类型定义

- 类注解组合是否与规范模板一致（如 Controller 四件套、`@RequiredArgsConstructor` 构造器注入）；
- Service 接口/实现包位置、是否误建 `impl` 子包；
- 返回体构造方式（`R.ok().build(...)` 等）、分页字段、校验分组、文档注解是否合规；
- 服务间契约：签名接口是否带注解、`@FeignClient` 子接口与降级落位、`contextId`、`@IgnoreAuth`/`@FeignIgnoreAuth` 配对。

## 检查项 4：禁止事项

逐条核对规范「禁止事项 & 踩坑提醒」章，典型包括：依赖注入方式、事务内 Feign/消息调用、吞异常、`SELECT *`/`${}`、手动填充审计字段、硬编码错误码与魔法值、未判空使用 `resp.getData()`、`@Value` 散落配置、敏感信息入库/入日志。以项目规范实际列出的条目为准，不外推。

## 检查项 5：问题清单 + 修改建议格式

每条问题按此结构输出：

```
### N. [严重度] 问题标题
- 位置：文件路径:行号（粘贴代码片段时标注片段内位置）
- 违反规范：〈章节号 章节名〉「规范原文引用」
- 现状：一句话说明代码当前写法
- 建议：符合规范的具体改法（贴最小修改示例）
```

严重度分三级：**结构红线**（分层/依赖方向/契约落位）、**禁止事项**、**命名与写法**。

## 检查项 6：只报真实违规

- 每条问题的「违反规范」必须能在规范文档中找到原文，找不到就不报；
- 规范未涉及的领域（如规范没规定异常信息国际化）不提建议；
- 可以在结论末尾附一句"另有 N 处规范未规定、仅提示参考"的观察，但明确声明不属于违规，且不展开。
